Synthetic and Bridge Methods in Java

This article provides a comprehensive overview of synthetic and bridge methods in Java, explaining what they are, why the Java compiler automatically generates them, and how they function under the hood. You will learn the mechanical differences between the two, common scenarios where they appear—such as generic type erasure and nested class access—and how to detect them using Java reflection and bytecode inspection tools.

Understanding Synthetic Methods

A synthetic method is any method, field, or constructor introduced automatically by the Java compiler (javac) that does not explicitly exist in the source code. These artifacts are marked with the ACC_SYNTHETIC bytecode flag.

The Java compiler introduces synthetic constructs to bridge the gap between high-level Java language features and low-level Java Virtual Machine (JVM) constraints, enabling advanced language capabilities without altering JVM specifications.

Common Scenario: Accessing Private Members in Nested Classes

Prior to the introduction of Nest-Based Access Control in Java 11 (JEP 181), the JVM did not permit inner classes to directly access private members of their enclosing classes, or vice-versa. At the bytecode level, the enclosing class and inner class are treated as separate top-level classes.

To circumvent this limitation, the compiler created package-private synthetic static accessor methods:

public class Outer {
    private int secret = 42;

    class Inner {
        void printSecret() {
            // Accesses Outer.access$000(Outer) behind the scenes in Java 8 and earlier
            System.out.println(secret);
        }
    }
}

Other common instances of synthetic methods include:

  • The values() and valueOf(String) methods generated for enum types.
  • Generated fields and methods supporting lambda expressions and method references.
  • Synthetic switch tables generated when switching over enum values.

Understanding Bridge Methods

A bridge method is a specialized category of synthetic method. While all bridge methods are synthetic, not all synthetic methods are bridge methods. In the bytecode, they are marked with both ACC_SYNTHETIC and ACC_BRIDGE flags.

Bridge methods are generated almost exclusively to preserve polymorphism, method overriding, and binary backward compatibility in the presence of generic type erasure.

Common Scenario: Generic Type Erasure and Method Overriding

When Java compiles generic code, it removes all generic type arguments via type erasure, replacing them with their raw bounds (often Object). This creates a signature mismatch when a class implements a parameterized interface or overrides a generic method with a more specific type.

Consider the following example:

public interface Producer<T> {
    T produce();
}

public class StringProducer implements Producer<String> {
    @Override
    public String produce() {
        return "Hello World";
    }
}

After type erasure, the interface definition becomes:

public interface Producer {
    Object produce();
}

Because StringProducer specifies String produce(), the JVM no longer sees this as a valid implementation of Object produce() due to differing return type descriptors.

To satisfy the interface contract at the bytecode level, the compiler injects a bridge method into StringProducer:

// Compiler-generated bridge method
public Object produce() {
    return this.produce(); // delegates to String produce()
}

When invoking produce() via the Producer interface reference, the JVM invokes the Object produce() bridge method, which immediately delegates to the specialized String produce() method.

Key Differences

Feature Synthetic Method Bridge Method
Bytecode Flag ACC_SYNTHETIC ACC_SYNTHETIC and ACC_BRIDGE
Primary Purpose Language feature support (e.g., inner classes, enums) Resolving generic type erasure and covariance conflicts
Visibility Hidden from source code, usually package-private Hidden from source code, matches overriding method's visibility
Relationship Broad category of compiler-generated methods Specific subcategory of synthetic methods

How to Detect Synthetic and Bridge Methods

You can detect compiler-generated methods programmatically through the Java Reflection API or statically through bytecode disassembly.

Using Reflection

The java.lang.reflect.Method class provides built-in methods to inspect these flags:

for (Method method : StringProducer.class.getDeclaredMethods()) {
    System.out.printf("Method: %-20s Synthetic: %-5s Bridge: %-5s%n",
        method.getName(),
        method.isSynthetic(),
        method.isBridge()
    );
}

Using javap

You can inspect the bytecode using the Java class file disassembler (javap) with the private (-p) and verbose (-v) flags:

javap -p -v StringProducer.class

In the output, bridge methods display attributes indicating their status:

public java.lang.Object produce();
  flags: (0x1041) ACC_PUBLIC, ACC_BRIDGE, ACC_SYNTHETIC
  Code:
    stack=1, locals=1, args_size=1
       0: aload_0
       1: invokevirtual #2 // Method produce:()Ljava/lang/String;
       4: areturn

Java Surrogate Pairs: codePointAt and codePointCount

Java String instances store text using UTF-16 encoding, which represents characters using 16-bit char values. While standard Basic Multilingual Plane (BMP) characters occupy a single char, supplementary characters—such as emojis and certain mathematical or historical symbols—require a surrogate pair of two consecutive 16-bit values. The codePointAt and codePointCount methods in Java bypass the limitations of naive 16-bit indexing by recognizing these surrogate pairs and processing them as single 32-bit Unicode code points.

Understanding UTF-16 Surrogate Pairs

Supplementary characters fall in the Unicode range from U+10000 to U+10FFFF. In UTF-16, these cannot fit into a single 16-bit char. Java splits each supplementary character into:

  1. High Surrogate (Leading): A value between \uD800 and \uDBFF.
  2. Low Surrogate (Trailing): A value between \uDC00 and \uDFFF.

When a method encounters a high surrogate immediately followed by a low surrogate, it must treat both char elements as one logical character.

How codePointAt(int index) Operates

The codePointAt(int index) method retrieves the 32-bit Unicode code point at a specified char index. Its internal traversal follows this sequence:

  1. It inspects the char at the specified index.
  2. It checks whether this character is a high surrogate using Character.isHighSurrogate(c1).
  3. If it is a high surrogate and index + 1 is within the string's bounds, it inspects the next character (c2).
  4. If c2 is a valid low surrogate (Character.isLowSurrogate(c2)), the method combines c1 and c2 using the supplementary character decoding algorithm and returns the resulting 32-bit int value.
  5. If the character at index is not a high surrogate, or if it is an unpaired surrogate, the method returns the character's numeric value directly as an int.

Because indexing operates on underlying 16-bit char offsets rather than code point offsets, calling codePointAt on the index of the low surrogate returns only the numeric value of that isolated trailing surrogate.

How codePointCount(int beginIndex, int endIndex) Operates

The codePointCount(int beginIndex, int endIndex) method calculates the actual number of Unicode code points within a substring range. A basic length() call returns the total number of 16-bit char units, which inflates the count for supplementary characters.

The codePointCount method resolves this with the following logic:

  1. It initializes a counter to zero and iterates a pointer from beginIndex up to endIndex.
  2. At each step, it checks the character at the current index.
  3. If the character is a high surrogate and the following character (still within endIndex) is a low surrogate, it increments the pointer by 2 to skip the entire pair, but increments the code point counter by only 1.
  4. If the character is not part of a valid pair, it increments the pointer by 1 and the code point counter by 1.
  5. The process continues until the pointer reaches endIndex, returning the accurate count of full Unicode symbols.

Example Walkthrough

Consider a string containing an emoji: "A\uD83D\uDE00B" (which renders as "A😀B").

  • Length: str.length() returns 4 because the emoji requires two char units (\uD83D and \uDE00).
  • codePointAt(0): Returns 65 (Unicode for 'A').
  • codePointAt(1): Detects the high surrogate \uD83D and the following low surrogate \uDE00, returning 128512 (the code point for 😀).
  • codePointAt(2): Evaluates index 2 directly, finding the low surrogate \uDE00 in isolation, returning 56832.
  • codePointCount(0, 4): Evaluates 'A' (1), the pair \uD83D\uDE00 (1), and 'B' (1), returning a total of 3.

Java String Interpolation and Template Processors

This article explains the concept of string interpolation, examines why traditional Java lacked native support for it, and explores how modern Java addresses this feature through template processors. You will learn the mechanics behind String Templates, how they balance developer ergonomics with security, and how template processors differentiate Java's approach from other modern programming languages.

What Is String Interpolation?

String interpolation is a language feature that allows developers to evaluate expressions or variables directly inside a string literal. Instead of relying on manual concatenation or positional format specifiers, developers can embed references seamlessly.

In languages like JavaScript, Kotlin, or C#, string interpolation typically looks like this:

// C# example
string message = $"Hello, {name}!";

// JavaScript example
let message = `Hello, ${name}!`;

Before the introduction of String Templates, Java developers relied on three primary alternatives:

  • Concatenation (+ operator): Verbose, visually cluttered, and hard to read with complex expressions.
  • StringBuilder: Efficient for multiple mutations, but unnecessarily verbose for simple messages.
  • String.format() / formatted(): Cleaner than concatenation, but separates the values from their target positions and introduces runtime type mismatch risks.

String Templates in Java

Java introduced String Templates as a preview feature (via JEP 430 in JDK 21 and JEP 459 in JDK 22). Rather than offering naive string interpolation—which directly merges raw text and variable values into an immutable string—Java decoupled the template from the evaluation phase.

Java's implementation relies on three components:

  1. A Template Processor: An object that handles the template and its embedded expressions.
  2. A Dot (.): Separates the processor from the template literal.
  3. A Template Literal: A string containing embedded expressions enclosed within \{...}.

The standard syntax appears as:

String name = "Alice";
String greeting = STR."Hello, \{name}!";

In this example, STR is a built-in template processor, and \{name} is an embedded expression evaluated at runtime.

How Template Processors Work

A template processor is an implementation of the StringTemplate.Processor functional interface. When Java encounters a template, it does not immediately construct a String. Instead, the compiler transforms the literal into a StringTemplate object.

A StringTemplate contains:

  • Fragments: The static, literal portions of the text.
  • Values: The computed results of the embedded expressions.

The template processor receives these fragments and values, processes them, and returns an arbitrary result type—not strictly a String.

Standard Processors

Modern Java drafts introduced built-in processors to handle common scenarios:

  • STR: Evaluates embedded expressions, converts them to strings via String.valueOf(), and concatenates them with the static fragments.
  • FMT: Similar to STR, but allows format specifiers directly within the expression brackets to control layout, alignment, and precision: 
    String record = FMT."Item: %-10s\{item} | Price: %7.2f\{price}";
  • RAW: Does not evaluate or concatenate the template automatically. It returns the raw StringTemplate object containing the unevaluated components, useful for passing templates directly to custom processors.

Why Java Avoided Naive Interpolation: The Security Advantage

The primary motivation for Java’s template processor design is security. In naive string interpolation, untrusted user input directly interpolated into a query string easily leads to vulnerabilities like SQL injection or Cross-Site Scripting (XSS).

Consider a database query:

// Naive interpolation risk:
String query = $"SELECT * FROM users WHERE name = '{userInput}'";

If userInput contains malicious SQL code, the resulting string compromises the system.

Java solves this by allowing custom processors that intercept the raw fragments and values before a final query is formed:

PreparedStatement ps = DB."SELECT * FROM users WHERE name = \{userInput}";

In this architecture, the DB processor parses the template into a parameterized query with placeholders (?) and safely binds userInput as a parameter, neutralizing injection risks entirely at compile and execution boundaries.

Summary

String interpolation in Java evolves beyond basic syntactic sugar. By channeling interpolation through template processors, Java allows direct variable embedding while granting processors full control over the parsing, validation, and final output type, establishing a balance between developer readability and critical application security.

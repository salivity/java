Java Repeatable Annotations and Containing Wrappers

This article provides a comprehensive overview of repeatable annotations in Java, introduced in Java 8, and explores the internal mechanics of the containing annotation wrapper. You will learn why repeatable annotations were introduced, how to define and use them with the @Repeatable meta-annotation, how the compiler uses container annotations for backward compatibility, and how to access these annotations at runtime using the Java Reflection API.

Understanding Repeatable Annotations

Prior to Java 8, applying the same annotation more than once to a single program element (such as a class, field, or method) resulted in a compile-time error. Developers were forced to use a grouping or "container" annotation manually to wrap multiple instances.

Java 8 introduced the @java.lang.annotation.Repeatable meta-annotation, allowing the same annotation to be applied repeatedly to a declaration in a clean, readable syntax without manually writing the wrapper every time.

How the Containing Annotation Wrapper Works

While Java allows you to write repeated annotations directly in source code, the Java Virtual Machine (JVM) bytecode structure was not altered to support multiple annotations of the same type directly. To maintain backward compatibility, the Java compiler automatically packages repeated annotations into a "containing annotation" (or wrapper annotation).

Under the hood:

  1. When you repeat an annotation, the compiler generates bytecode that wraps all instances into an array within the designated container annotation.
  2. The repeatable annotation must explicitly declare its container using the @Repeatable meta-annotation.
  3. The container annotation must define a value() method that returns an array of the repeatable annotation type.

Defining a Repeatable Annotation and Its Container

To create a repeatable annotation, you must define two separate annotation types: the repeatable annotation itself and its containing annotation wrapper.

Step 1: Create the Container Annotation

The container must have a value() element whose return type is an array of the repeatable annotation. Its @Retention and @Target meta-annotations must encompass the retention and target scopes of the contained annotation.

import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.annotation.ElementType;

@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.TYPE, ElementType.METHOD})
public @interface Roles {
    Role[] value();
}

Step 2: Create the Repeatable Annotation

Annotate the repeatable definition with @Repeatable, referencing the container class.

import java.lang.annotation.Repeatable;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.annotation.ElementType;

@Repeatable(Roles.class)
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.TYPE, ElementType.METHOD})
public @interface Role {
    String value();
}

Using Repeatable Annotations

Once configured, the annotation can be repeated directly on a target without manually wrapping it in @Roles:

@Role("ADMIN")
@Role("MANAGER")
public class DashboardService {
    // Class implementation
}

During compilation, the compiler translates the above code into the equivalent legacy syntax:

@Roles({
    @Role("ADMIN"),
    @Role("MANAGER")
})
public class DashboardService {
    // Class implementation
}

Retrieving Repeatable Annotations via Reflection

To support repeatable annotations, the Reflection API (AnnotatedElement interface) includes methods capable of looking through the container wrapper:

  • getAnnotationsByType(Class<T>): Unpacks the containing annotation and returns an array of the repeated annotations directly (Role[]).
  • getDeclaredAnnotationsByType(Class<T>): Similar to getAnnotationsByType, but ignores inherited annotations.
  • getAnnotation(Class<T>): If multiple annotations are present, calling getAnnotation(Role.class) returns null because the bytecode contains the wrapper (Roles), not a standalone Role. To read the container directly, call getAnnotation(Roles.class).
public class ReflectionDemo {
    public static void main(String[] args) {
        // Direct retrieval of individual repeated annotations
        Role[] roles = DashboardService.class.getAnnotationsByType(Role.class);
        for (Role role : roles) {
            System.out.println(role.value()); // Prints "ADMIN", then "MANAGER"
        }

        // Direct retrieval of the wrapper
        Roles container = DashboardService.class.getAnnotation(Roles.class);
        System.out.println(container.value().length); // Prints 2
    }
}

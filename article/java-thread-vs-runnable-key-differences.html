Java Thread vs Runnable: Key Differences

In Java, multithreading can be achieved primarily by either extending the Thread class or implementing the Runnable interface. While both approaches define code that executes on a separate execution path, they differ fundamentally in design, flexibility, and architectural principles. Implementing Runnable separates the task logic from the thread execution mechanism and avoids Java's single inheritance limitation, making it the preferred approach in modern software development. Extending the Thread class tightly couples the task to the execution thread itself.

Core Concepts

  • Thread Class: A class located in java.lang that implements the Runnable interface. It provides built-in methods to control and manage thread lifecycle behaviors, such as start(), sleep(), join(), and interrupt().
  • Runnable Interface: A functional interface with a single abstract method: public void run(). It represents an abstract unit of work intended to be executed by a thread.

Key Differences

1. Object-Oriented Design and Inheritance

Java supports single inheritance; a class can extend only one parent class.

  • Extending Thread: Once a class extends Thread, it cannot inherit from any other class. This restricts your domain model design.
  • Implementing Runnable: A class implementing Runnable is free to extend another base class (for example, public class WorkerTask extends BaseTask implements Runnable), preserving object-oriented flexibility.

2. Separation of Concerns

  • Extending Thread: Tightly couples the task definition (what needs to be done) with the thread of execution (how it runs).
  • Implementing Runnable: Separates the task from the runner. The class implementing Runnable represents the task itself, while an instance of Thread or an ExecutorService acts as the execution engine.

3. Resource Sharing and Reusability

  • Extending Thread: Each instance of your class represents an entirely separate thread. Sharing state across multiple threads requires extra synchronization or static variables.
  • Implementing Runnable: A single Runnable instance can be passed to multiple Thread objects. This makes it simple to share common resources across multiple concurrently executing workers.

4. Thread Pooling and Concurrency Frameworks

Modern Java development rarely creates threads directly using new Thread(). Instead, high-performance applications use the java.util.concurrent package (such as ExecutorService).

  • Extending Thread: Creating and discarding custom Thread objects wastes memory and CPU time because threads are expensive system resources. Thread pools cannot easily recycle Thread subclasses as plain tasks.
  • Implementing Runnable: Thread pools directly accept Runnable tasks, executing them using recycled worker threads.

Implementation Examples

Extending Thread

public class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Running inside: " + Thread.currentThread().getName());
    }

    public static void main(String[] args) {
        MyThread thread = new MyThread();
        thread.start(); // Starts execution on a new thread
    }
}

Implementing Runnable

public class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("Running inside: " + Thread.currentThread().getName());
    }

    public static void main(String[] args) {
        Thread thread = new Thread(new MyTask());
        thread.start(); // Passes task to a thread wrapper and starts it
    }
}

Since Runnable is a functional interface, it can also be written concisely using lambda expressions:

Thread thread = new Thread(() -> System.out.println("Running inline task"));
thread.start();

Summary of When to Use Which

  • Use Runnable: In almost all scenarios. It adheres to standard design patterns, supports lambda expressions, works seamlessly with thread pools, and preserves inheritance hierarchies.
  • Extend Thread: Only when you are developing a specialized thread management library or need to override core behaviors of the Thread class itself, such as specialized thread scheduling or custom lifecycle management.

CompletableFuture: thenApply vs thenAccept vs thenRun

In Java's asynchronous programming model, CompletableFuture provides several methods to chain dependent tasks once an asynchronous computation completes. The fundamental difference between thenApply, thenAccept, and thenRun lies in their input parameters and return values: thenApply takes the previous result and returns a new result, thenAccept takes the previous result but returns nothing (Void), and thenRun neither takes the previous result nor returns a value. Choosing the correct method depends entirely on whether your subsequent stage needs to read the incoming data, produce new data, or simply execute a side effect.

thenApply: Transform and Return

thenApply is used when you want to transform the result of the previous stage into a new value. It accepts a Function<T, R> as a parameter. It receives the result of the preceding CompletableFuture, applies a transformation, and returns a new CompletableFuture<R> containing the transformed value.

CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> "42")
    .thenApply(s -> "The answer is " + s);

// Result: CompletableFuture<String> containing "The answer is 42"

Use thenApply when:

  • You need to process or map the output of the preceding stage.
  • The downstream stages require the transformed result for further processing.

thenAccept: Consume Without Returning

thenAccept is used when you need to consume the result of the previous stage to perform an action (such as logging, updating a database, or rendering to a UI) without producing a new value. It accepts a Consumer<T> as a parameter and returns a CompletableFuture<Void>.

CompletableFuture<Void> future = CompletableFuture.supplyAsync(() -> "Order #1001")
    .thenAccept(order -> System.out.println("Processing: " + order));

// Result: CompletableFuture<Void>

Use thenAccept when:

  • You need the result of the previous computation to perform a side effect.
  • The pipeline does not need to pass data to subsequent stages.

thenRun: Execute an Action Independently

thenRun is used when you simply want to execute a task after the previous stage completes, but you do not care about the result of that stage. It accepts a Runnable as a parameter. It takes no inputs and returns a CompletableFuture<Void>.

CompletableFuture<Void> future = CompletableFuture.supplyAsync(() -> "Data Saved")
    .thenRun(() -> System.out.println("Operation finished successfully."));

// Result: CompletableFuture<Void>

Use thenRun when:

  • The execution of the next step depends solely on the completion of the previous step.
  • You do not need access to the data computed by the previous stage.

Comparison Summary

Method Functional Interface Accepts Argument? Returns a Value? Resulting Type
thenApply Function<T, R> Yes (from previous stage) Yes CompletableFuture<R>
thenAccept Consumer<T> Yes (from previous stage) No (void) CompletableFuture<Void>
thenRun Runnable No No (void) CompletableFuture<Void>

Async Variants

Each of these methods also has asynchronous counterparts: thenApplyAsync, thenAcceptAsync, and thenRunAsync. While the standard methods execute in the same thread that completed the previous stage (or the calling thread if already complete), the *Async variants offload the execution to the ForkJoinPool.commonPool() or a custom-provided Executor. The input/output contract regarding parameters and return types remains identical.

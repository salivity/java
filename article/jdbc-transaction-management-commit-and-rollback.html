JDBC Transaction Management: Commit and Rollback

Managing database transactions in Java using the Java Database Connectivity (JDBC) API allows developers to execute multiple SQL operations as a single, atomic unit of work. By default, JDBC operates in an auto-commit mode where every individual SQL statement is treated as its own transaction and immediately persisted to the database. To group multiple operations together and ensure data integrity—satisfying the Atomicity, Consistency, Isolation, and Durability (ACID) properties—JDBC provides the setAutoCommit(), commit(), and rollback() methods on the java.sql.Connection interface.

Disabling Auto-Commit with setAutoCommit(false)

By default, every newly established JDBC Connection has auto-commit enabled (true). In this state, the database automatically commits the changes after each statement executes, making it impossible to undo prior statements if a subsequent one fails.

To begin a manual transaction boundary, you must disable auto-commit:

connection.setAutoCommit(false);

Once auto-commit is set to false, no changes made by INSERT, UPDATE, or DELETE statements are permanently saved to the database until explicitly instructed. All subsequent operations are buffered within the context of the current transaction.

Persisting Changes with commit()

When all statements within a logical unit of work complete successfully without any errors, you invoke the commit() method:

connection.commit();

Calling commit() makes all modifications performed since the start of the transaction permanent and visible to other database sessions. It also releases any database locks held by the transaction, successfully finalizing the atomic batch.

Reverting Changes with rollback()

If any operation within the transaction fails—typically signaled by a SQLException—you must cancel the entire sequence of operations to prevent data corruption or partial state changes. This is handled by the rollback() method:

connection.rollback();

Calling rollback() discards all changes made during the active transaction, reverting the database to the exact state it was in before the transaction began. Like commit(), rolling back also releases locks held by the transaction.

Standard Implementation Pattern

Transaction management in JDBC typically follows a try-catch pattern to ensure that failures trigger a rollback, and resources are cleanly reset and closed.

Connection connection = null;
try {
    connection = dataSource.getConnection();
    
    // 1. Begin transaction
    connection.setAutoCommit(false);

    // 2. Execute SQL operations
    try (PreparedStatement withdrawStmt = connection.prepareStatement("UPDATE accounts SET balance = balance - ? WHERE id = ?");
         PreparedStatement depositStmt = connection.prepareStatement("UPDATE accounts SET balance = balance + ? WHERE id = ?")) {

        withdrawStmt.setBigDecimal(1, amount);
        withdrawStmt.setLong(2, fromAccountId);
        withdrawStmt.executeUpdate();

        depositStmt.setBigDecimal(1, amount);
        depositStmt.setLong(2, toAccountId);
        depositStmt.executeUpdate();
    }

    // 3. Commit if all statements succeed
    connection.commit();

} catch (SQLException e) {
    // 4. Rollback if any statement fails
    if (connection != null) {
        try {
            connection.rollback();
        } catch (SQLException rollbackEx) {
            rollbackEx.printStackTrace();
        }
    }
    throw e;
} finally {
    // 5. Restore default state and release connection
    if (connection != null) {
        try {
            connection.setAutoCommit(true);
            connection.close();
        } catch (SQLException closeEx) {
            closeEx.printStackTrace();
        }
    }
}

Key Considerations

  • Resetting Auto-Commit: When using connection pools (such as HikariCP or Apache DBCP), always reset connection.setAutoCommit(true) before returning the connection to the pool to prevent unintended transaction states in subsequent operations.
  • Nested Rollback Handling: The rollback() method can also throw a SQLException, so it must be enclosed in its own try-catch block inside the main error-handling logic.
  • Savepoints: For finer control within large transactions, JDBC also supports the setSavepoint() and rollback(Savepoint savepoint) methods, which allow partial rollbacks to designated milestones without aborting the entire transaction.

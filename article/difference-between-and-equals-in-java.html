Difference Between == and equals() in Java

In Java, comparing data can be accomplished using either the == identity operator or the equals() method, but they serve fundamentally different purposes. This guide breaks down the core distinctions between the two, explaining how the == operator handles primitive values and memory references, while the equals() method evaluates logical object equivalence. Understanding this distinction is essential for avoiding subtle bugs, particularly when working with strings, wrapper classes, and custom objects.

The Identity Operator (==)

The == operator is a binary operator built directly into the Java language. Its behavior depends entirely on whether it is operating on primitive types or object references:

  • Primitive Types: When used with primitives (int, boolean, char, double, etc.), == compares the raw binary values. If both operands hold the same value (for example, 5 == 5), the expression evaluates to true.
  • Reference Types (Objects): When used with objects, == does not look at the internal data or state of the objects. Instead, it checks reference equality, meaning it verifies whether both variables point to the exact same memory address in the heap. If two separate objects contain identical data but reside in different memory locations, == evaluates to false.

The equals() Method

The equals() method is defined in the root java.lang.Object class and is intended to determine logical equality (value equality).

  • Default Behavior: By default, the equals() implementation in java.lang.Object simply uses the == operator (return (this == obj);). Therefore, unless a class overrides this method, equals() behaves identically to ==.
  • Overridden Behavior: Most standard Java library classes—such as String, Integer, Date, and collection classes—override equals() to compare the meaningful internal state of the objects rather than their memory addresses. Developers can also override equals() in custom classes to define what makes two instances logically equal.

Key Differences at a Glance

Feature The == Operator The equals() Method
Type Built-in operator Method defined in java.lang.Object
Customization Cannot be overridden (no operator overloading) Can be overridden by any class
Primitive Support Works with primitive types and object references Works only with objects
Primary Purpose Checks value (primitives) or memory address (objects) Checks logical content/state equality
Null Handling Safe; obj == null evaluates without exceptions Calling null.equals(...) throws a NullPointerException

The String Comparison Example

The difference between reference equality and logical equality is most clearly illustrated using Java String objects:

String s1 = new String("hello");
String s2 = new String("hello");

// Reference comparison: false because s1 and s2 are distinct objects in memory
boolean referenceCheck = (s1 == s2); 

// Value comparison: true because String overrides equals() to check characters
boolean contentCheck = s1.equals(s2);

While string literals may sometimes evaluate to true with == due to Java's internal String Constant Pool optimization, relying on == for text or object comparison is dangerous.

Best Practices

Use == when comparing primitive data types or when you explicitly need to confirm that two object references point to the exact same instance in memory. For all other object comparisons where you care about the actual data—such as comparing strings or checking whether two domain models represent the same entity—always use the equals() method, or utility methods like java.util.Objects.equals(a, b) to safely handle potential null values.

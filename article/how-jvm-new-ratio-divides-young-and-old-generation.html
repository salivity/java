How JVM NewRatio Divides Young and Old Generation

The -XX:NewRatio JVM parameter defines the proportional sizing between the young and old generations within the Java heap memory. By establishing a fixed mathematical ratio between the tenured space (old generation) and the nursery (young generation), this setting dictates how dynamically allocated memory is partitioned to balance object allocation throughput against garbage collection pauses. This article breaks down the mathematical mechanics of NewRatio, provides calculation examples, and outlines how the JVM applies this configuration in runtime environments.

The Mechanics of the NewRatio Formula

In the Java Virtual Machine (JVM), the total heap is primarily split into two main physical areas: the Young Generation (which contains the Eden and Survivor spaces) and the Old (Tenured) Generation.

The -XX:NewRatio=n parameter defines the ratio of the Old Generation size to the Young Generation size as n:1. In this setup, n represents the multiplier for the Old Generation relative to one unit of the Young Generation.

The memory distribution is calculated using the following formulas:

  • Young Generation Size = Total Heap / (NewRatio + 1)
  • Old Generation Size = Total Heap * (NewRatio / (NewRatio + 1))

Calculation Examples

To understand how the heap divides in practice, consider a JVM configured with an 8 GB heap (-Xms8g -Xmx8g).

Example 1: Default Server Configuration (-XX:NewRatio=2)

On most modern 64-bit server JVMs, the default value for NewRatio is 2. This sets the ratio of Old to Young generation at 2:1.

  • Young Generation: 8 GB / (2 + 1) = 8 GB / 3 ≈ 2.67 GB (33.3% of the heap)
  • Old Generation: 8 GB * (2 / 3) ≈ 5.33 GB (66.7% of the heap)

Example 2: Larger Old Generation (-XX:NewRatio=3)

Setting -XX:NewRatio=3 establishes a 3:1 ratio, giving three parts to the Old Generation for every one part assigned to the Young Generation.

  • Young Generation: 8 GB / (3 + 1) = 8 GB / 4 = 2 GB (25% of the heap)
  • Old Generation: 8 GB * (3 / 4) = 6 GB (75% of the heap)

Example 3: Equal Distribution (-XX:NewRatio=1)

Setting -XX:NewRatio=1 creates a 1:1 relationship, splitting the heap equally between both generations.

  • Young Generation: 8 GB / (1 + 1) = 4 GB (50% of the heap)
  • Old Generation: 8 GB / (1 + 1) = 4 GB (50% of the heap)

Precedence and Overriding Flags

The JVM prioritizes explicit size constraints over ratio-based flags. If you configure explicit young generation sizes using -Xmn, -XX:NewSize, or -XX:MaxNewSize, the JVM ignores -XX:NewRatio.

For ratio-based sizing to take effect, ensure that:

  1. -Xmn is not specified.
  2. Initial and maximum young generation bounds (-XX:NewSize and -XX:MaxNewSize) are not hardcoded to fixed values that conflict with the calculated ratio.

Practical Use Cases

  • Decrease NewRatio (Increase Young Gen): Useful for applications with high object churn where the vast majority of objects die young (e.g., stateless microservices, web request routers). A larger young generation allows minor garbage collections to clean up short-lived objects without prematurely promoting them to the Old Generation.
  • Increase NewRatio (Increase Old Gen): Useful for stateful applications that maintain large in-memory caches, long-lived session stores, or large object graphs that survive minor collections and must reside in the Old Generation without causing frequent full GC cycles.

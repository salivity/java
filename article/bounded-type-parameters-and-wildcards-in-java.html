Bounded Type Parameters and Wildcards in Java

Java generics enhance type safety by allowing classes, interfaces, and methods to operate on objects of various types while providing compile-time type checking. This article covers the core mechanics of bounded type parameters and wildcards in Java generics. You will learn how bounded type parameters restrict the types allowed in generic declarations, how unbounded, upper-bounded, and lower-bounded wildcards operate, and how to apply the PECS (Producer Extends, Consumer Super) principle to write flexible and robust code.

What Are Bounded Type Parameters?

A standard generic type parameter, such as <T>, acts as an unbounded placeholder that can be replaced by any object type. Bounded type parameters restrict the allowable types that can be substituted for that parameter, allowing access to the methods defined in the bounding types.

Upper Bounded Type Parameters

To declare an upper bounded type parameter, use the extends keyword followed by the class or interface name. This restricts the type argument to either the specified type or its subclasses (or implementers).

public class NumericBox<T extends Number> {
    private T value;

    public NumericBox(T value) {
        this.value = value;
    }

    public double getDoubleValue() {
        // Safe to call Number methods directly
        return value.doubleValue();
    }
}

In this example, T can only be instantiated with Number or its subtypes, such as Integer, Double, or Float. Attempting to use String results in a compile-time error.

Multiple Bounds

Java allows a type parameter to have multiple bounds. If one of the bounds is a class, it must be listed first, followed by any interface bounds separated by the & symbol:

public <T extends Number & Comparable<T>> void process(T item) {
    // T has access to both Number and Comparable methods
}

How Wildcards Work in Java Generics

While type parameters introduce a named type variable (like T), a wildcard represents an unknown type, denoted by the question mark symbol (?). Wildcards are primarily used as type arguments for parameters, fields, or local variables to increase flexibility.

1. Unbounded Wildcards (?)

The unbounded wildcard represents any type. It is useful when a method only relies on functionality provided by the Object class, or when code uses methods in the generic class that do not depend on the type parameter (such as List.size() or List.clear()).

public void printList(List<?> list) {
    for (Object elem : list) {
        System.out.println(elem);
    }
}

A List<?> can accept a List<String>, List<Integer>, or any other list. However, you cannot insert elements (other than null) into a collection typed with an unbounded wildcard because the compiler cannot verify the element's compatibility.

2. Upper Bounded Wildcards (? extends Type)

An upper bounded wildcard restricts the unknown type to a specific type or a subtype of that type. It is specified using ? extends Type.

public double sumOfList(List<? extends Number> list) {
    double sum = 0.0;
    for (Number n : list) {
        sum += n.doubleValue();
    }
    return sum;
}

This method accepts List<Integer>, List<Double>, or List<Number>. Because the exact type is unknown at compile time, you can read from the list as a Number, but you cannot add new items to it (except null).

3. Lower Bounded Wildcards (? super Type)

A lower bounded wildcard restricts the unknown type to a specific type or a supertype (ancestor) of that type. It is specified using ? super Type.

public void addIntegers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
    list.add(3);
}

This method can accept a List<Integer>, List<Number>, or List<Object>. Lower bounded wildcards allow you to write elements of the specified type into the collection safely.

The PECS Guideline

When deciding between upper and lower bounded wildcards, use the PECS rule: Producer extends, Consumer super.

  • Producer (extends): If a parameterized type represents a producer that supplies data to your code (you read from it), use ? extends Type.
  • Consumer (super): If a parameterized type represents a consumer that accepts data from your code (you write to it), use ? super Type.
  • Both Read and Write: If you need to both produce and consume elements from the same collection, do not use wildcards; use an exact type parameter (such as List<T>).

Bounded Type Parameters vs. Wildcards

  • Bounded Type Parameters (<T extends Number>): Introduce an explicit type variable. Use these when you need to refer to the type throughout the method body, return a value of that specific type, or enforce relationships between multiple arguments.
  • Wildcards (List<? extends Number>): Represent an anonymous unknown type. Use these to make method signatures more flexible for callers when the specific type does not need to be captured or reused.

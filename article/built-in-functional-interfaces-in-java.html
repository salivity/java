Built-In Functional Interfaces in Java

The java.util.function package, introduced in Java 8, provides a comprehensive set of built-in functional interfaces designed to serve as target types for lambda expressions and method references. This article breaks down the four fundamental categories of functional interfaces—Predicates, Functions, Suppliers, and Consumers—along with their primitive and multi-argument specializations to help you write cleaner, more idiomatic functional code in Java.

1. The Four Core Interfaces

Almost all interfaces in java.util.function derive from four primary shapes determined by input parameters and return types:

Interface Method Signature Description
Predicate<T> boolean test(T t) Evaluates a condition on input T and returns a boolean.
Function<T, R> R apply(T t) Accepts argument T and produces a result of type R.
Consumer<T> void accept(T t) Accepts argument T and performs an operation without returning a result.
Supplier<T> T get() Takes no arguments and produces a result of type T.

Examples of Core Interfaces

  • Predicate<T>: Used for filtering or conditional checks. 
    Predicate<String> isNotEmpty = s -> !s.isEmpty();
  • Function<T, R>: Used for transforming data from one type to another. 
    Function<String, Integer> stringLength = s -> s.length();
  • Consumer<T>: Used for side effects such as logging or printing. 
    Consumer<String> printer = s -> System.out.println(s);
  • Supplier<T>: Used for lazy generation of values or object factories. 
    Supplier<Double> randomValue = () -> Math.random();

2. Two-Arity (Bi-) Specializations

When an operation requires two inputs instead of one, Java provides two-argument variations:

  • BiPredicate<T, U>: boolean test(T t, U u) — Evaluates two inputs and returns a boolean.
  • BiFunction<T, U, R>: R apply(T t, U u) — Transforms two inputs into a single output.
  • BiConsumer<T, U>: void accept(T t, U u) — Performs an operation on two inputs without returning a result.

(Note: There is no BiSupplier because a supplier takes no arguments.)

3. Operator Specializations

Operators are specialized forms of Function where the input and output types are identical.

  • UnaryOperator<T>: Extends Function<T, T>. Takes a single operand of type T and returns a result of the same type T. 
    UnaryOperator<String> toUpperCase = s -> s.toUpperCase();
  • BinaryOperator<T>: Extends BiFunction<T, T, T>. Takes two operands of type T and returns a result of type T. 
    BinaryOperator<Integer> add = (a, b) -> a + b;

4. Primitive Specializations

To avoid the performance overhead of boxing and unboxing primitives (int, long, double), the package includes specialized interfaces:

Primitive Predicates, Consumers, and Suppliers

  • Predicates: IntPredicate, LongPredicate, DoublePredicate
  • Consumers: IntConsumer, LongConsumer, DoubleConsumer
  • Suppliers: IntSupplier, LongSupplier, DoubleSupplier, BooleanSupplier

Primitive Functions and Operators

  • Input-specific Functions: IntFunction<R>, LongFunction<R>, DoubleFunction<R>
  • Output-specific Functions: ToIntFunction<T>, ToLongFunction<T>, ToDoubleFunction<T>
  • Primitive-to-Primitive Functions: IntToLongFunction, IntToDoubleFunction, LongToIntFunction, LongToDoubleFunction, DoubleToIntFunction, DoubleToLongFunction
  • Primitive Operators:
    • Unary: IntUnaryOperator, LongUnaryOperator, DoubleUnaryOperator
    • Binary: IntBinaryOperator, LongBinaryOperator, DoubleBinaryOperator
  • Two-Arity Primitive Variations: ObjIntConsumer<T>, ObjLongConsumer<T>, ObjDoubleConsumer<T>, ToIntBiFunction<T, U>, ToLongBiFunction<T, U>, ToDoubleBiFunction<T, U>

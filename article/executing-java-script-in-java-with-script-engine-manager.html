Executing JavaScript in Java with ScriptEngineManager

The ScriptEngineManager class is the entry point for Java's Scripting API (defined under JSR 223), enabling Java applications to seamlessly discover, instantiate, and execute external scripting languages such as JavaScript, Groovy, or Python. This article explains the internal architecture of ScriptEngineManager, how it discovers language runtimes dynamically, and how it shares state and executes code directly inside the Java Virtual Machine (JVM).

The Discovery Mechanism: JSR 223 and Service Provider Interface (SPI)

ScriptEngineManager relies on Java's standard ServiceLoader mechanism to find available scripting engines on the runtime classpath. When a ScriptEngineManager instance is created, it scans META-INF/services/javax.script.ScriptEngineFactory files located inside loaded JARs.

Each compliant scripting engine provides an implementation of the ScriptEngineFactory interface. This factory defines the engine's metadata, such as supported language names, aliases, MIME types, and file extensions. When you request an engine by name—for example, using manager.getEngineByName("JavaScript")—the manager queries its registered factories to find a match and returns an initialized ScriptEngine instance.

Instantiation and Engine Types for JavaScript

The underlying JavaScript engine depends on your Java version:

  • Rhino: Used in Java 6 and 7, developed by Mozilla.
  • Nashorn: Introduced in Java 8 as a high-performance successor that compiled JavaScript directly to JVM bytecode. It was deprecated in Java 11 and removed in Java 15.
  • GraalVM JavaScript: The modern standard for running JavaScript on the JVM in Java 15 and newer, added via external dependencies.

Regardless of the underlying runtime, the interaction pattern remains identical through the uniform ScriptEngine interface.

The Execution Lifecycle

Executing a script involves three core steps: passing the script, managing context/bindings, and invoking the evaluation mechanism.

1. Code Evaluation

The primary execution method is engine.eval(), which accepts either a String or a java.io.Reader. The engine parses the script into an abstract syntax tree (AST) and either interprets it directly or compiles it to bytecode at runtime, depending on the engine's design.

import javax.script.ScriptEngine;
import javax.script.ScriptEngineManager;

public class ScriptExample {
    public static void main(String[] args) throws Exception {
        ScriptEngineManager manager = new ScriptEngineManager();
        ScriptEngine engine = manager.getEngineByName("JavaScript");

        // Simple script execution
        Object result = engine.eval("var x = 10; var y = 20; x + y;");
        System.out.println(result); // Outputs: 30
    }
}

2. Bi-Directional Data Binding

Java and the scripting engine share data through the Bindings interface, which is a key-value map backing the script's global scope. Java objects can be injected directly into the script environment, and script-generated variables can be extracted back into Java.

// Pass Java variables into the JavaScript scope
engine.put("name", "Alice");

// Modify or use them inside the script
engine.eval("var greeting = 'Hello, ' + name;");

// Retrieve values back into Java
String greeting = (String) engine.get("greeting");

3. Invoking Functions and Compilation

If an engine implements the Invocable interface, Java can call specific script functions directly without re-evaluating the entire script body. Additionally, engines implementing the Compilable interface allow scripts to be precompiled into a CompiledScript object, drastically improving performance for scripts evaluated repeatedly.

Through this combination of SPI service discovery, unified evaluation methods, and shared context bindings, ScriptEngineManager decouples the host Java application from the scripting language implementation, enabling robust polyglot execution inside the JVM.

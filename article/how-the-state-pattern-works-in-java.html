How the State Pattern Works in Java

The State design pattern allows an object in Java to alter its behavior at runtime when its internal state changes, making it appear as if the object changed its class. This article explores the architecture of the State pattern, demonstrates how it replaces bulky conditional statements with polymorphic behavior, and provides a clear Java implementation showing state transitions in action.

Core Mechanics of the State Pattern

In traditional object-oriented programming, altering behavior based on state often involves extensive if-else or switch statements evaluated against an enum or integer flag. This approach leads to fragile, tightly coupled code that violates the Open/Closed Principle.

The State pattern resolves this by encapsulating state-specific behavior into distinct classes that implement a common interface. The primary object, known as the Context, maintains a reference to an instance of a Concrete State. Instead of handling operations directly, the Context delegates execution to the current state object. When a state transition occurs, the Context updates its internal state reference to a new Concrete State instance, instantly changing how subsequent calls are executed.

Key Components

  1. Context: Maintains an instance of a Concrete State that defines the current state, exposing a public interface to clients and delegating state-specific requests to the current state object.
  2. State Interface: Defines the contract for all operations that depend on the internal state.
  3. Concrete States: Classes that implement the State interface, each providing distinct behavior corresponding to a specific state of the Context.

Implementation in Java

Consider a media player with distinct playback states.

1. The State Interface

public interface PlayerState {
    void pressPlay(MediaPlayer player);
    void pressStop(MediaPlayer player);
}

2. Concrete States

Each concrete state encapsulates the behavior corresponding to that condition and triggers transitions when appropriate:

public class PausedState implements PlayerState {
    @Override
    public void pressPlay(MediaPlayer player) {
        System.out.println("Resuming playback.");
        player.setState(new PlayingState());
    }

    @Override
    public void pressStop(MediaPlayer player) {
        System.out.println("Already stopped or paused.");
    }
}

public class PlayingState implements PlayerState {
    @Override
    public void pressPlay(MediaPlayer player) {
        System.out.println("Pausing playback.");
        player.setState(new PausedState());
    }

    @Override
    public void pressStop(MediaPlayer player) {
        System.out.println("Stopping playback.");
        player.setState(new StoppedState());
    }
}

public class StoppedState implements PlayerState {
    @Override
    public void pressPlay(MediaPlayer player) {
        System.out.println("Starting playback.");
        player.setState(new PlayingState());
    }

    @Override
    public void pressStop(MediaPlayer player) {
        System.out.println("Player is already stopped.");
    }
}

3. The Context

The MediaPlayer class delegates actions to its active PlayerState object:

public class MediaPlayer {
    private PlayerState state;

    public MediaPlayer() {
        // Initial state
        this.state = new StoppedState();
    }

    public void setState(PlayerState state) {
        this.state = state;
    }

    public void pressPlay() {
        state.pressPlay(this);
    }

    public void pressStop() {
        state.pressStop(this);
    }
}

4. Execution

public class Main {
    public static void main(String[] args) {
        MediaPlayer player = new MediaPlayer();

        player.pressPlay(); // Outputs: Starting playback. (Transitions to PlayingState)
        player.pressPlay(); // Outputs: Pausing playback. (Transitions to PausedState)
        player.pressPlay(); // Outputs: Resuming playback. (Transitions to PlayingState)
        player.pressStop(); // Outputs: Stopping playback. (Transitions to StoppedState)
    }
}

Why Use the State Pattern in Java?

  • Eliminates Conditional Complexity: Eliminates repetitive and error-prone switch or if-else blocks spread across the codebase.
  • Single Responsibility Principle: Isolates the logic for each state into its own class, simplifying maintenance and unit testing.
  • Open/Closed Principle: New states can be introduced by creating new classes implementing the state interface without modifying existing state logic or the context.

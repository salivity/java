Java Custom Serialization: writeObject and readObject

Custom serialization in Java allows developers to override the standard binary serialization mechanism by defining private writeObject and readObject methods within a Serializable class. This article explains how the Java Virtual Machine (JVM) detects and invokes these methods, how to selectively serialize fields, encrypt sensitive data, and validate object integrity during deserialization.

The Custom Serialization Mechanism

When an object is serialized using ObjectOutputStream.writeObject(), the JVM checks whether the target class implements the java.io.Serializable interface. By default, it traverses the object graph and serializes all non-transient, non-static fields.

However, if the class declares explicit writeObject and readObject methods with specific signatures, the standard serialization engine bypasses its automatic behavior and delegates the process to these custom methods.

Exact Method Signatures

The JVM relies on reflection to locate these methods. They must have the exact signatures shown below, including the private access modifier:

private void writeObject(java.io.ObjectOutputStream out) throws java.io.IOException;
private void readObject(java.io.ObjectInputStream in) throws java.io.IOException, ClassNotFoundException;

Declaring them as private ensures that subclasses cannot accidentally override them and external classes cannot directly invoke them, preserving encapsulation.

How writeObject Works

The writeObject method is responsible for saving the state of the object. Typically, the first operation inside this method is invoking out.defaultWriteObject(). This method handles the serialization of all standard, non-transient fields automatically.

After defaultWriteObject() executes, you can write additional data or handle transient fields manually using primitive write methods (such as writeInt, writeUTF, or writeObject).

private void writeObject(ObjectOutputStream out) throws IOException {
    // Write standard non-transient fields
    out.defaultWriteObject();
    
    // Custom logic: Encrypt or format sensitive/transient data
    String encryptedPassword = encrypt(this.password);
    out.writeObject(encryptedPassword);
}

How readObject Works

The readObject method reconstructs the object from the stream. Mirroring writeObject, the first step is usually invoking in.defaultReadObject(). This restores standard fields to their serialized values.

Following defaultReadObject(), custom reading logic is executed in the exact order in which data was written in writeObject.

private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException {
    // Read standard non-transient fields
    in.defaultReadObject();
    
    // Custom logic: Read and decrypt the custom data
    String encryptedPassword = (String) in.readObject();
    this.password = decrypt(encryptedPassword);
    
    // Validate object state to prevent deserialization attacks
    validateState();
}

Common Use Cases

  • Handling Non-Serializable Fields: If a class holds a reference to a third-party object that does not implement Serializable, that field can be marked transient, and its underlying data can be manually extracted and written.
  • Security and Data Obfuscation: Sensitive fields (like tokens or passwords) marked as transient can be encrypted before being written to the output stream and decrypted upon reading.
  • State Validation: Deserialization creates objects without calling constructors. Implementing readObject allows you to validate invariant constraints before the object is fully restored.
  • Performance Optimization: Bypassing standard serialization for large or complex internal data structures allows you to write only the bare minimum data required to recreate the state.

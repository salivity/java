Method Hiding vs Overriding for Java Static Methods

In Java, the fundamental difference between method overriding and method hiding lies in how method calls are resolved—either dynamically at runtime or statically at compile time. While non-static instance methods use method overriding to enable runtime polymorphism based on the actual object instance, static methods cannot be overridden. Instead, defining a static method in a subclass with the same signature as one in the superclass results in method hiding. This article examines the mechanics of method hiding versus method overriding, illustrating how reference types, binding mechanisms, and class inheritance govern their behavior.

Core Differences

The primary distinction stems from whether a method belongs to an individual object instance or to the class itself.

  • Method Overriding (Runtime Polymorphism): Applies exclusively to non-static instance methods. The Java Virtual Machine (JVM) determines which implementation to execute at runtime based on the actual object type created in memory, regardless of the reference type used.
  • Method Hiding (Compile-Time Resolution): Applies to static methods. Because static methods belong to the class rather than any instance, the JVM resolves the call at compile time based strictly on the declared reference type of the variable, not the underlying runtime object.

Method Type Instance (non-static) Class (static)

How Method Overriding Works

When a subclass provides a specific implementation of an instance method already defined in its superclass, it overrides that method.

class Parent {
    void display() {
        System.out.println("Parent instance method");
    }
}

class Child extends Parent {
    @Override
    void display() {
        System.out.println("Child instance method");
    }
}

If you invoke this method using a superclass reference holding a subclass instance:

Parent obj = new Child();
obj.display(); // Output: "Child instance method"

The runtime environment inspects the object created via new Child() and executes the subclass implementation.

How Method Hiding Works

When a subclass defines a static method with the exact same signature as a static method in its superclass, the subclass method hides the superclass method instead of overriding it.

class Parent {
    static void printMessage() {
        System.out.println("Parent static method");
    }
}

class Child extends Parent {
    // This hides Parent.printMessage()
    static void printMessage() {
        System.out.println("Child static method");
    }
}

Invoking the method through a reference variable reveals the compile-time binding:

Parent obj = new Child();
obj.printMessage(); // Output: "Parent static method"

Because obj is declared as type Parent, the compiler binds the call directly to Parent.printMessage(), ignoring the fact that obj references an instance of Child.

Key Rules and Best Practices

  1. Do Not Mix Static and Non-Static: A static method cannot hide an instance method of the same signature from a superclass, nor can an instance method override a static method. Attempting either results in a compile-time error.
  2. Avoid Invoking Static Methods via References: To avoid confusion caused by method hiding, always invoke static methods using the class name directly (e.g., Parent.printMessage() or Child.printMessage()) rather than through an instance variable.
  3. Compiler Checks: Applying the @Override annotation to a static method in a subclass will trigger a compilation error, as the compiler recognizes that static members cannot participate in polymorphic overriding.

Shallow Copy vs Deep Copy in Java Explained

In Java, duplicating an object is primarily achieved through either shallow copying or deep copying, each determining how nested references are handled in memory. A shallow copy duplicates the primary object while sharing references to any internal objects, meaning modifications to inner data affect both copies. In contrast, a deep copy recursively duplicates the object and all nested instances, creating a completely independent copy. This guide explains the core mechanics, implementation techniques, and key differences between these two copying approaches.

What is a Shallow Copy?

A shallow copy creates a new instance of an object and copies all of its fields directly to the new instance. For primitive data types (such as int, boolean, or double), the actual values are duplicated. However, for reference types (such as arrays, collections, or custom objects), only the memory addresses (references) are copied.

Because the references point to the exact same memory locations on the heap, both the original and copied objects share the same nested objects. Modifying the state of a nested mutable object through either instance will immediately reflect in the other.

How to Implement a Shallow Copy

The most common way to create a shallow copy is by using the default clone() method provided by java.lang.Object:

public class Address {
    public String city;
    public Address(String city) { this.city = city; }
}

public class User implements Cloneable {
    public String name;
    public Address address;

    public User(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    @Override
    public Object clone() throws CloneNotSupportedException {
        return super.clone(); // Performs a shallow copy by default
    }
}

If you modify userCopy.address.city, the originalUser.address.city will also change because both instances reference the same Address object.

What is a Deep Copy?

A deep copy creates a new instance of the object and recursively duplicates every object referenced by it. Rather than copying references, new memory is allocated on the heap for every nested object.

Because no references are shared between the original and the new instance, the two objects are entirely independent. Changes made to any part of the copied object graph have no effect on the original object graph.

How to Implement a Deep Copy

Deep copies can be implemented using several methods depending on the complexity of the object structure.

1. Copy Constructors

Manually instantiating nested objects within a copy constructor is often the cleanest and most explicit approach:

public class Address {
    public String city;

    public Address(String city) { this.city = city; }
    
    // Copy constructor for Address
    public Address(Address other) {
        this.city = other.city;
    }
}

public class User {
    public String name;
    public Address address;

    public User(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    // Deep copy constructor for User
    public User(User other) {
        this.name = other.name;
        this.address = new Address(other.address); // Creates a new nested instance
    }
}

2. Overriding the clone() Method

You can override clone() to explicitly clone internal references:

@Override
public User clone() throws CloneNotSupportedException {
    User cloned = (User) super.clone();
    cloned.address = new Address(this.address.city);
    return cloned;
}

3. Serialization

For deep object graphs, serializing the object to JSON or byte streams and deserializing it into a new instance guarantees a complete deep copy without writing manual copy logic for every nested field.

Key Differences

Feature Shallow Copy Deep Copy
Object Isolation Dependent on shared mutable references Completely independent
Nested Objects References are copied (shared memory) Objects are fully duplicated (new memory)
Performance Fast execution and minimal memory usage Slower execution and higher memory overhead
Implementation Complexity Simple (default clone() or shallow assignment) Complex (requires manual recursion or serialization)
Side Effects High risk of unintended mutations No risk of unintended mutations

When to Use Each Approach

Use a shallow copy when:

  • The object contains only primitive values or immutable objects (such as String, Integer, or LocalDate).
  • The shared state is intentional for caching or resource sharing.
  • Performance and memory constraints are critical, and nested objects will never be modified.

Use a deep copy when:

  • The object contains mutable nested structures that must be modified independently.
  • You need to pass an isolated snapshot of an object to another thread or external API.
  • You must ensure strict encapsulation and eliminate side-effects across components.

Java Regex Lookahead and Lookbehind Assertions

This article explains how lookahead and lookbehind assertions—collectively known as lookarounds—function within Java regular expressions. Lookarounds are zero-width mechanisms that determine whether a match should succeed based on what follows or precedes the current position in the target text, without including those characters in the final match result. You will learn the syntax, evaluation logic, and Java-specific implementation rules for both positive and negative lookaround assertions.

The Concept of Zero-Width Assertions

Standard regular expression tokens consume characters as the matching engine moves from left to right across an input string. Once a character is consumed, it becomes part of the matched substring, and the engine's match pointer advances past it.

Lookarounds are zero-width assertions. Instead of consuming text, they assert whether a condition is true at a specific boundary or position. The engine pauses at the current index, looks ahead or behind to test the subpattern, and then resets the index back to the starting point. If the condition is met, the engine continues processing the remainder of the pattern; if it fails, the engine backtracks or abandons the match at that position.

Lookahead Assertions

Lookahead assertions evaluate text to the right of the current matching index.

Positive Lookahead: (?=X)

A positive lookahead succeeds only if the subpattern X matches the text immediately following the current position.

  • Syntax: (?=pattern)
  • Example: \d+(?=px)
  • Evaluation: When applied to "1920px", the engine matches 1920 using \d+. It then encounters (?=px) and checks if "px" immediately follows. Because it does, the assertion succeeds. The final match returned is 1920. The letters "px" are verified but not consumed.

Negative Lookahead: (?!X)

A negative lookahead succeeds only if the subpattern X does not match the text immediately following the current position.

  • Syntax: (?!pattern)
  • Example: \d+(?!px)
  • Evaluation: When applied to "100em", the digits 100 are matched. The engine checks if "px" follows. Because "em" follows instead of "px", the negative condition evaluates to true, and 100 is returned as a valid match.

Lookbehind Assertions

Lookbehind assertions evaluate text to the left of the current matching index.

Positive Lookbehind: (?<=X)

A positive lookbehind succeeds only if the subpattern X matches the text immediately preceding the current position.

  • Syntax: (?<=pattern)
  • Example: (?<=\$)\d+
  • Evaluation: When applied to "$50", the engine encounters (?<=\$). It inspects the character immediately before the digits. Since $ is present, the assertion passes, and the engine consumes and returns 50. The currency symbol is excluded from the match.

Negative Lookbehind: (?<!X)

A negative lookbehind succeeds only if the subpattern X does not match the text immediately preceding the current position.

  • Syntax: (?<!pattern)
  • Example: (?<!\$)\d+
  • Evaluation: When applied to "€50", the engine checks the character preceding 50. Since it is € and not $, the negative assertion succeeds, returning 50.

Java-Specific Evaluation Constraints

The java.util.regex engine handles lookarounds with specific rules regarding pattern length and backtracking:

  1. Finite Length Requirement for Lookbehind: Unlike lookahead assertions, Java's implementation of lookbehind requires that the pattern inside (?<=...) or (?<!...) has an obvious maximum length.

    • Unbounded quantifiers such as * and + will throw a PatternSyntaxException at compile time (e.g., (?<=\w+) is invalid).
    • Bounded quantifiers with fixed or maximum limits are permitted (e.g., (?<=\w{1,5}) is valid).
    • Alternation of strings with different lengths is allowed as long as each alternative is finite (e.g., (?<=cat|dog|bird)).

  2. Order of Execution: The Java regex engine evaluates lookaround assertions at the exact point they appear in the regular expression sequence. If placed at the start of a pattern, the lookaround checks the prefix; if placed at the end, it checks the suffix. Placing multiple lookarounds side by side acts as a logical AND condition, requiring all assertions to pass at that specific index for the match to proceed.

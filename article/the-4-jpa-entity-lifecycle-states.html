The 4 JPA Entity Lifecycle States

In the Java Persistence API (JPA), managing data efficiently requires understanding how entities transition between different states during their lifecycle. This article explores the four core entity lifecycle states managed within the Java persistence architecture—New (Transient), Managed, Detached, and Removed—detailing their defining characteristics, their relationship with the persistence context, and how they interact with the database.

1. New (Transient)

An entity is in the New (or Transient) state when it has been instantiated using the standard Java new operator but has not yet been associated with a JPA EntityManager or persistence context.

Key characteristics include:

  • It does not represent any row in the database.
  • It does not have a persistent database identity (primary key value), unless explicitly assigned manually.
  • The persistence provider does not track any modifications made to this object.
  • Invoking entityManager.persist(entity) transitions the entity from the New state to the Managed state.

2. Managed (Persistent)

An entity is Managed when it is actively associated with a persistence context and possesses a database identity.

Key characteristics include:

  • It directly corresponds to a row in the database or will correspond to one once the transaction commits.
  • The EntityManager actively tracks any state changes made via the entity's setter methods through dirty checking.
  • Changes are automatically synchronized (flushed) to the database at the end of the transaction without needing an explicit update call.
  • Entities become Managed when retrieved via entityManager.find(), loaded through a JPQL/Criteria query, saved via persist(), or brought back into context via merge().

3. Detached

An entity enters the Detached state when it has a persistent identity and corresponds to a database record, but is no longer actively tracked by a persistence context.

Key characteristics include:

  • Changes made to a detached entity are ignored by the persistence provider and are not written to the database.
  • Entities become detached when the EntityManager closes, when explicitly evicted using entityManager.detach(entity), or when the persistence context is wiped using entityManager.clear().
  • A detached entity can be re-associated with an active persistence context by calling entityManager.merge(entity), which copies the state to a new managed instance.

4. Removed

An entity is in the Removed state when it is associated with an active persistence context but is marked for deletion from the underlying database.

Key characteristics include:

  • The entity still exists in Java memory, but its corresponding row will be deleted upon transaction commit or flush.
  • It is placed into this state by calling entityManager.remove(entity) on an already managed entity.
  • If a removed entity is re-persisted via persist() before the transaction commits, the removal operation is cancelled and the entity returns to the Managed state.

Java String Concatenation with invokedynamic Explained

This article explores how modern Java compilers handle string concatenation using the invokedynamic bytecode instruction introduced in Java 9 via JEP 280. You will learn how the compiler delegates concatenation logic to the runtime library via StringConcatFactory, replacing traditional StringBuilder chains, and how the Java Virtual Machine (JVM) dynamically optimizes memory allocation and performance during execution without requiring bytecode recompilation.

The Traditional Approach: Pre-Java 9

Prior to Java 9, the Java compiler (javac) translated every string concatenation expression (using the + operator) into explicit bytecode instructions involving StringBuilder (or StringBuffer in earlier versions). For example, the expression String s = "Hello, " + name + "!"; was compiled into:

  1. A new java/lang/StringBuilder instruction.
  2. A call to the StringBuilder constructor.
  3. Repeated .append(...) calls for each component.
  4. A final .toString() call.

While functional, this approach had significant drawbacks. It generated bloated bytecode, baked a specific concatenation strategy directly into class files, and forced unnecessary object allocations. If a faster or more memory-efficient strategy became available in a newer JVM, existing compiled code could not benefit from it without being recompiled.

The Shift to invokedynamic (JEP 280)

Java 9 introduced JEP 280 (Indify String Concatenation), changing how javac processes the + operator. Instead of emitting explicit calls to StringBuilder, the compiler now emits a single invokedynamic (often abbreviated as indy) instruction.

The invokedynamic instruction delays the choice of the concatenation recipe and execution strategy until runtime. The bytecode merely declares:

  • The dynamic arguments (variables to concatenate).
  • The expected return type (java.lang.String).
  • A reference to a bootstrap method (BSM) responsible for linking the call site.

The Bootstrap Method: StringConcatFactory

When the JVM encounters an invokedynamic string concatenation call site for the first time, it invokes a bootstrap method located in java.lang.invoke.StringConcatFactory. The two primary bootstrap methods are:

  • makeConcat: Used when there are only dynamic arguments and no static constants.
  • makeConcatWithConstants: Used when the concatenation includes static string literals alongside dynamic arguments.

The Recipe and Constants

When using makeConcatWithConstants, the compiler packages static literals into a "recipe" string using special marker characters:

  • \u0001 represents an ordinary dynamic argument passed at runtime.
  • \u0002 represents a constant passed via the constant pool.

For example, compiling "User: " + user + " (id: " + id + ")" creates a recipe structured like:

"User: \u0001 (id: \u0001)"

The compiler attaches this recipe and any constant values as static bootstrap arguments in the class file's constant pool.

Runtime Linkage and Optimization Strategies

The bootstrap method executes only once per call site. When invoked, StringConcatFactory analyzes the argument types and generates an optimized CallSite containing a MethodHandle that performs the actual concatenation.

StringConcatFactory provides several selectable strategies controlled by the system property java.lang.invoke.stringConcat:

  1. MethodHandle Inline (Default): The runtime constructs a tree of method handles that pre-computes the exact length of the resulting string by querying the lengths of individual arguments. It then allocates a byte array (byte[]) of the exact required capacity and directly writes the characters into it, utilizing Java's compact strings storage model (Latin-1 or UTF-16).
  2. Bytecode Generator: Dynamically generates an anonymous class via bytecode injection to perform the array allocation and copying.
  3. StringBuilder Fallback: Constructs a basic StringBuilder chain, similar to the pre-Java 9 mechanism, mostly used as a baseline or debug fallback.

Under-the-Hood Execution Flow

The full lifecycle of modern string concatenation operates in three steps:

  1. Compilation: javac encounters "Count: " + count. It outputs an invokedynamic instruction targeting StringConcatFactory.makeConcatWithConstants with recipe "Count: \u0001".
  2. Bootstrapping (First Run): The JVM executes the bootstrap method. The factory examines the dynamic types (e.g., an int), determines the optimal low-level method handle sequence to size and fill a single string storage buffer, and returns a constant CallSite.
  3. Subsequent Invocations: The JVM bypasses the bootstrap method entirely. It executes the linked method handle directly, which the JIT compiler can inline and optimize down to direct memory operations, avoiding intermediate heap objects entirely.

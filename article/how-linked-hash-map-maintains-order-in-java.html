How LinkedHashMap Maintains Order in Java

Java's LinkedHashMap extends HashMap to preserve the order of its elements, supporting either insertion order or access order. While a standard HashMap offers \(O(1)\) performance, it does not guarantee any predictable iteration order because entries are distributed across hash buckets. LinkedHashMap solves this by augmenting the hash table with an internal doubly-linked list running through all of its entries. This article explains the underlying data structure of LinkedHashMap, how it tracks insertion order by default, and how it switches to access order using internal lifecycle hooks.

The Underlying Data Structure: Doubly-Linked Entries

A standard HashMap stores entries in buckets using a singly-linked list or a red-black tree (instances of HashMap.Node). LinkedHashMap inherits this hashing structure but substitutes the standard node with its own static nested class, LinkedHashMap.Entry<K,V>.

This class extends HashMap.Node<K,V> by adding two additional reference fields:

  • before: Points to the previous entry in the iteration sequence.
  • after: Points to the next entry in the iteration sequence.

In addition to these pointers within each entry, the LinkedHashMap instance maintains two global references:

  • head: Points to the first entry in the sequence (the oldest entry in insertion order or the least-recently used in access order).
  • tail: Points to the most recently added or accessed entry.

When iterating over a LinkedHashMap, Java traverses this linked list from head to tail using the after pointers, completely bypassing the empty buckets in the hash table.

Maintaining Insertion Order

By default, LinkedHashMap maintains insertion order. When a key-value pair is inserted, the map must store it in the appropriate hash bucket while also placing it at the end of the doubly-linked list.

HashMap provides empty hook methods specifically designed for subclasses. During a put() operation, LinkedHashMap overrides the newNode() factory method:

  1. The entry is hashed and placed into the appropriate bucket, just like a standard HashMap.
  2. The overridden newNode() method instantiates LinkedHashMap.Entry and calls an internal helper method, linkNodeLast(p).
  3. linkNodeLast() updates the entry’s before pointer to the current tail, updates the current tail.after pointer to the new entry, and sets the map's tail reference to this new entry.

If a key already exists and put() is called with a new value, the value is updated, but the entry's position in the linked list remains unchanged under insertion-order mode.

Maintaining Access Order

LinkedHashMap can also order entries based on how recently they were accessed, making it a foundational component for creating Least Recently Used (LRU) caches. This behavior is enabled using a specialized constructor:

public LinkedHashMap(int initialCapacity, float loadFactor, boolean accessOrder)

Setting accessOrder to true alters how read and update operations behave. Whenever an entry is read or updated via methods such as get(), getOrDefault(), put() (for an existing key), or replace(), the map invokes the post-access hook:

void afterNodeAccess(Node<K,V> e)

When accessOrder is enabled, afterNodeAccess() performs the following pointer adjustments:

  1. It unlinks the accessed node e from its current position by linking e.before directly to e.after.
  2. It relinks e to the end of the list by pointing tail.after to e and e.before to the old tail.
  3. It updates the tail pointer to reference e.

Through this mechanism, any accessed element is moved to the tail of the list. Over time, the least recently used element automatically drifts to the head, while the most recently used element always resides at the tail.

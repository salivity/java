Maven Build Lifecycle: Compile, Test, and Deploy

Apache Maven manages Java project workflows through a standardized build lifecycle framework that defines the exact order in which tasks are executed. This article explains how Maven structures its built-in lifecycle phases to transition raw source code through compilation, automated testing, packaging, and final deployment to remote repositories.

Understanding the Build Lifecycle Concept

Maven operates on three built-in build lifecycles: clean (handles project cleaning), site (handles project site documentation creation), and default (handles project build and deployment).

The default lifecycle manages the entire process from compilation to deployment. It consists of sequential, ordered steps called phases. Executing a specific phase automatically executes every preceding phase in that lifecycle. Each phase delegates its actual work to underlying goals provided by Maven plugins.

The Compilation Phases

The compilation stage prepares the environment and converts Java source code into bytecode:

  1. validate: Validates whether the project structure is correct and all necessary metadata in the pom.xml is available.
  2. generate-sources / process-sources: Generates any needed source code (such as annotation-processor generated classes) and modifies them.
  3. process-resources: Copies and filters static resources (from src/main/resources) into the target output directory so they are available on the runtime classpath.
  4. compile: Invokes the maven-compiler-plugin to compile the production source code found in src/main/java and places the compiled .class files into the target/classes directory.

The Testing Phases

Maven isolates test execution from production code to ensure non-production dependencies do not pollute the final build output:

  1. test-compile: Compiles the source files located in src/test/java using the compiled production code and test-scoped dependencies on the classpath. Test classes are placed into target/test-classes.
  2. process-test-resources: Copies configuration files and resources from src/test/resources into the test target directory.
  3. test: Executes unit tests using test frameworks like JUnit or TestNG via the maven-surefire-plugin. If any unit test fails, the build halts immediately by default, preventing unverified code from being packaged.

Packaging and Verification

Once tests pass successfully, Maven prepares the compiled classes for distribution:

  1. package: Assembles the compiled code and resources into their distributable format, defined by the <packaging> element in pom.xml (e.g., JAR, WAR, or EAR), using plugins such as maven-jar-plugin.
  2. pre-integration-test / integration-test: Sets up environments and executes tests that require the packaged application to be running via the maven-failsafe-plugin.
  3. post-integration-test: Cleans up resources or environments initialized during integration testing.
  4. verify: Checks integration test results to verify the package meets quality criteria.

The Deployment Phases

The final phases distribute the verified artifact:

  1. install: Uses the maven-install-plugin to install the package into your local machine's repository cache (~/.m2/repository). This allows other locally built Maven projects to consume it as a dependency.
  2. deploy: Invoked in a continuous integration/continuous deployment (CI/CD) environment. The maven-deploy-plugin copies the final artifact, along with its associated POM and metadata, to a shared remote repository (such as Nexus, Artifactory, or Maven Central) specified in the <distributionManagement> section of the project configuration.

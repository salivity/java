Java Reflection: Inspect Classes and Private Members

The Java Reflection API allows programs to examine and modify their own runtime behavior, enabling developers to discover internal class structures, inspect metadata, and bypass standard access control mechanisms. By querying the Java Virtual Machine (JVM) for an object's underlying Class instance, applications can dynamically uncover declared constructors, fields, and methods, and even read or execute private members that are otherwise inaccessible under standard compilation rules.

Inspecting Classes at Runtime

Runtime inspection begins with obtaining an instance of java.lang.Class. This can be achieved through three primary entry points:

  • Using the class literal: MyClass.class
  • Calling getClass() on an existing instance: obj.getClass()
  • Loading by fully qualified name dynamically: Class.forName("com.example.MyClass")

Once the Class object is loaded, the reflection API provides methods to inspect its structure:

  • getFields() vs. getDeclaredFields(): getFields() returns all public fields, including inherited ones. getDeclaredFields() returns all fields declared directly by the class, including private, protected, and package-private fields, but excludes inherited fields.
  • getMethods() vs. getDeclaredMethods(): Similar to fields, getDeclaredMethods() retrieves every method declared directly within the class, regardless of its access modifier.
  • getDeclaredConstructors(): Retrieves all constructors defined within the class.

These methods return reflection objects—Field, Method, and Constructor—from the java.lang.reflect package, each carrying metadata such as return types, parameter types, annotations, and modifiers (determined via Modifier.toString(member.getModifiers())).

Invoking Private Members

Under standard execution, calling a private method or reading a private field outside its declaring class triggers a compile-time or runtime access error. Java's Reflection API circumvents this using the AccessibleObject class, which is the superclass of Field, Method, and Constructor.

Reading and Writing Private Fields

To access a private field, obtain its Field definition using getDeclaredField(String name) and call setAccessible(true):

MyClass target = new MyClass();
Field privateField = MyClass.class.getDeclaredField("secretKey");

// Suppress Java language access control checks
privateField.setAccessible(true);

// Read value
Object value = privateField.get(target);

// Modify value
privateField.set(target, "newSecretValue");

Invoking Private Methods

To execute a private method, retrieve the Method object via getDeclaredMethod(String name, Class<?>... parameterTypes), set it to accessible, and call invoke():

MyClass target = new MyClass();
Method privateMethod = MyClass.class.getDeclaredMethod("calculateHash", String.class);

// Suppress access checks
privateMethod.setAccessible(true);

// Execute the method
Object result = privateMethod.invoke(target, "inputData");

How setAccessible(true) Works Internally

When code attempts to read a field or invoke a method directly, the JVM checks the caller's access privileges against the member's access modifiers (public, protected, private).

Calling setAccessible(true) toggles an internal boolean flag within the reflection object's implementation. When this flag is set, the standard JVM access check routines are skipped during subsequent get(), set(), or invoke() calls, allowing direct access to the memory reference or method pointer.

Restrictions in Modern Java (Java 9+)

Starting with Java 9 and the introduction of the Java Platform Module System (JPMS), strong encapsulation restricts deep reflection. If a class belongs to a named module, calling setAccessible(true) on its private members will throw an InaccessibleObjectException unless the module explicitly exports or opens that package to the caller using the opens directive in its module-info.java file.

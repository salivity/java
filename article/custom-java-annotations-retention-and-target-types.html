Custom Java Annotations: Retention and Target Types

Custom Java annotations provide structured metadata that can decorate elements like classes, methods, and variables without directly modifying program logic. To control how these annotations function, the Java language relies on two foundational meta-annotations: @Retention and @Target. @Retention dictates the lifecycle stage at which the annotation is preserved and accessible, while @Target restricts the specific syntax elements to which the annotation can be applied. Understanding and properly configuring these two attributes is essential for building robust, compile-time-safe, and reflection-friendly custom annotations.

The Role of Retention Policies

The retention policy of an annotation determines how long the Java compiler and the Java Virtual Machine (JVM) retain the metadata. It is defined using the @Retention meta-annotation, which accepts a value from the java.lang.annotation.RetentionPolicy enum:

  • RetentionPolicy.SOURCE: Annotations with this policy exist exclusively in the source code. The compiler discards them during compilation, meaning they do not appear in the compiled .class bytecode. Source-level annotations are primarily used by compile-time tools, linters, and code generators (such as Project Lombok or @Override).
  • RetentionPolicy.CLASS: This is the default retention policy if none is specified. The compiler records the annotation inside the .class file, but the JVM does not load or retain it into memory at runtime. This level is useful for build tools, static bytecode analyzers, or off-line bytecode instrumentation frameworks that parse .class files directly without executing them.
  • RetentionPolicy.RUNTIME: Annotations are recorded in the .class file and maintained in memory by the JVM during application execution. This allows the metadata to be read reflectively at runtime using methods such as Class.isAnnotationPresent() or Method.getAnnotation(). Frameworks such as Spring, Hibernate, and JUnit rely heavily on runtime retention to facilitate dependency injection, transaction management, and automated test execution.

Defining Applicable Contexts with Target Types

The target type defines the programmatic contexts where a custom annotation is legally allowed. It is configured using the @Target meta-annotation, which accepts an array of values from the java.lang.annotation.ElementType enum. If @Target is omitted, the annotation can be placed on almost any Java declaration.

Common ElementType values include:

  • ElementType.TYPE: Allows the annotation to be placed on classes, interfaces (including annotation types), records, or enums.
  • ElementType.FIELD: Restricts placement to fields, including enum constants.
  • ElementType.METHOD: Restricts placement strictly to methods.
  • ElementType.PARAMETER: Applies to method or constructor parameters, often used in REST API controllers for request binding.
  • ElementType.CONSTRUCTOR: Limits the annotation to constructors.
  • ElementType.LOCAL_VARIABLE: Allows decorating local variables inside methods (note: local variable annotations cannot be read via reflection, even with runtime retention).
  • ElementType.ANNOTATION_TYPE: Designates meta-annotations, restricting application only to other annotation declarations.
  • ElementType.TYPE_USE: Introduced in Java 8, this target allows an annotation to be used anywhere a type is used, including generic type arguments, casts, and implements clauses, enabling advanced static type checking.

Practical Implementation

To construct a custom annotation, declare it using the @interface syntax and apply both meta-annotations directly above the declaration:

package com.example.annotations;

import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.METHOD, ElementType.TYPE})
public @interface AuditLog {
    String action() default "DEFAULT_ACTION";
    int severity() default 1;
}

In this example, @Retention(RetentionPolicy.RUNTIME) ensures that application frameworks can inspect the @AuditLog metadata via reflection while the application is running. Concurrently, @Target({ElementType.METHOD, ElementType.TYPE}) instructs the compiler to permit the annotation only on class declarations or individual methods. If a developer attempts to annotate a private field or a method parameter with @AuditLog, the Java compiler immediately halts with a compilation error, enforcing strict and predictable usage across the codebase.

How JaCoCo Measures Line and Branch Coverage

JaCoCo (Java Code Coverage) measures code execution by using bytecode instrumentation to insert tracking probes directly into compiled Java classes. During automated test runs, these probes record which instructions and control flow paths execute. JaCoCo then maps this runtime execution data back to the original source code lines and decision branches, generating detailed line and branch coverage metrics without requiring modifications to your actual source code.

Bytecode Instrumentation and Runtime Probes

JaCoCo primarily operates via a Java Agent during test execution. As the Java Virtual Machine (JVM) loads .class files, the agent intercepts the bytecode and injects lightweight synthetic instructions known as probes.

A probe is essentially a boolean flag within an array allocated for each class (represented internally as a boolean[] structure). When an execution path reaches a probe, it sets the corresponding array index to true. This probe execution adds minimal runtime overhead. At the end of the test suite execution—or at predefined intervals—the state of these boolean arrays is dumped into an execution data file (commonly jacoco.exec).

How JaCoCo Measures Line Coverage

Line coverage in JaCoCo is a derived metric calculated from bytecode instruction coverage. Java compilers retain a mapping of source file line numbers to compiled bytecode instructions within the bytecode's LineNumberTable attribute.

  1. Instruction Execution: JaCoCo first calculates coverage at the basic instruction level (individual Java bytecode instructions).
  2. Source Line Mapping: JaCoCo inspects the LineNumberTable to determine which set of bytecode instructions belongs to each physical line of Java source code.
  3. Line State Classification: Based on the execution of the mapped instructions, JaCoCo assigns one of three statuses to each line:
    • Not Covered (Red): None of the bytecode instructions mapped to this line were executed.
    • Partially Covered (Yellow): Some, but not all, bytecode instructions mapped to this line were executed (for instance, a multi-instruction line where an exception interrupted execution midway).
    • Fully Covered (Green): All bytecode instructions associated with the line were executed.

How JaCoCo Measures Branch Coverage

Branch coverage measures whether all possible outcomes of decision points in the code are exercised. In Java bytecode, decision points exist as jump instructions (such as ifeq, ifne, if_icmpeq, tableswitch, or lookupswitch).

  1. Identifying Decision Points: JaCoCo analyzes the control flow graph (CFG) of each method to identify conditional jump instructions generated by language constructs such as if, switch, ternary operators (? :), and null checks.
  2. Inserting Probes at Branches: For every conditional jump, JaCoCo places probes along all outgoing edges of the control flow:
    • The target path (the jump is taken).
    • The fall-through path (the condition is false, and execution continues to the next instruction).
  3. Evaluating Branch Outcomes:
    • A standard if statement represents two branches: true and false. JaCoCo requires both paths to execute for 100% branch coverage on that statement.
    • A switch statement produces multiple branches depending on the number of case blocks and whether a default case is present.
  4. Branch Status Classification:
    • No Branches: The line contains no decision logic.
    • Partially Covered: One or more, but not all, conditional paths were evaluated during testing (e.g., an if condition was only ever evaluated as true).
    • Fully Covered: Every outgoing execution path from the decision point was traversed at least once during testing.

Final Report Generation

To produce final reports (HTML, XML, or CSV), the JaCoCo report generator pairs the binary jacoco.exec file with the original class files and source files. By correlating the executed probes recorded in the data file with the bytecode structures and source line mappings, JaCoCo computes exact totals and percentages for lines, instructions, branches, methods, and cyclomatic complexity.

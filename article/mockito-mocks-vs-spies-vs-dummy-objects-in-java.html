Mockito Mocks vs Spies vs Dummy Objects in Java

This article explains how the Mockito framework differentiates between mock objects, spy objects, and dummy test doubles during Java unit testing. It explores the technical mechanisms behind each double type—focusing on runtime bytecode generation, default invocation handling, and state delegation—while highlighting the specific Mockito APIs and internal checks used to identify and manage them.

Mock Objects

A mock object is an entirely synthetic implementation of a class or interface generated dynamically at runtime using Byte Buddy. Mockito creates a mock when you invoke Mockito.mock(Class<T> classToMock) or apply the @Mock annotation.

Internally, Mockito distinguishes a mock by attaching an invocation handler (MockHandler) to the generated subclass. By default, Mockito configures mocks with the Answers.RETURNS_DEFAULTS strategy. When any method on a mock is called:

  • It does not execute the original class logic.
  • It records the invocation metadata (arguments, order, execution count) for later verification.
  • It returns default values corresponding to the return type (e.g., null for objects, 0 for numbers, false for booleans, and empty collections for standard collection types) unless a specific behavior is configured via when(...).thenReturn(...).

Spy Objects

A spy is a partial mock that wraps an existing, real instance of a class. Spies are created using Mockito.spy(T object) or the @Spy annotation.

Mockito distinguishes a spy from a regular mock primarily through its default invocation behavior:

  • Real Method Delegation: Instead of returning default blank values, a spy's default answer is Answers.CALLS_REAL_METHODS. When a method is called on a spy, Mockito delegates the call directly to the underlying real object instance.
  • Selective Stubbing: You can override specific methods using doReturn(...).when(spy)... while allowing the rest of the object to execute its genuine business logic and maintain its internal state.
  • Interaction Tracking: Like mocks, spies are intercepted by Mockito's dynamic proxy mechanism, enabling full access to verification methods like verify(spy).methodName().

Dummy Objects

In software testing terminology, a dummy object is an object passed around merely to satisfy method signatures, parameter lists, or constructors, but its methods are never intentionally exercised or tested.

Mockito does not provide a specialized dummy() API because a dummy is a conceptual pattern rather than a distinct technological construct:

  • Plain Java Instances or Nulls: Dummies are frequently implemented as raw Java objects (e.g., new Object(), an empty string "", or simply null) if the method under test does not dereference them.
  • Mocks Used as Dummies: Developers often use an unstubbed Mockito mock (e.g., mock(Service.class)) as a dummy simply to fulfill a non-null dependency requirement. In this scenario, Mockito treats the object internally as a standard mock; it is only a "dummy" from the perspective of test design intent.

How Mockito Distinguishes Them Internally

Mockito provides internal utilities and metadata inspections to determine what kind of object it is dealing with:

  • Mock Detection: The utility method MockUtil.isMock(Object obj) checks whether an object was generated by Mockito's proxy generator and contains an internal Mockito interceptor. Plain dummy objects return false.
  • Spy Detection: The utility method MockUtil.isSpy(Object obj) verifies that the object is a mock and specifically inspects its MockCreationSettings. If the object was configured to delegate to a real instance and use CALLS_REAL_METHODS as its default answer, Mockito identifies it as a spy.

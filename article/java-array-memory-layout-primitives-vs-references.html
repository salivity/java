Java Array Memory Layout: Primitives vs References

In Java, understanding how data structures occupy memory is crucial for optimizing application performance and footprint. This article examines the internal memory layout of an array of primitive types compared to an array of object references on the Java Virtual Machine (JVM) heap. It breaks down the differences in object headers, data storage mechanisms, memory overhead, and CPU cache efficiency between the two layouts.

Common JVM Array Header

In Java, all arrays are first-class objects. Regardless of whether an array contains primitives or references, it resides on the heap and begins with a standard array object header. On a typical 64-bit JVM, this header consists of:

  • Mark Word (8 bytes): Stores runtime metadata, including hash code, identity, garbage collection age, and locking flags.
  • Klass Word (4 or 8 bytes): A pointer to the class metadata representing the array type. With Compressed Object Pointers (UseCompressedOops, enabled by default for heaps under 32 GB), this takes 4 bytes; otherwise, it is 8 bytes.
  • Array Length (4 bytes): A 32-bit signed integer storing the number of elements in the array.
  • Padding (0–4 bytes): Alignment bytes added to ensure the header aligns to an 8-byte boundary (typically resulting in a 16-byte header with compressed oops).

Memory Layout of Primitive Arrays

In a primitive array (such as int[], long[], or byte[]), the primitive values are stored inline in a single, contiguous block of memory directly following the array header.

[ Object Header (16 bytes) ] [ Primitive 0 ] [ Primitive 1 ] ... [ Primitive N-1 ] [ Padding ]

Key characteristics include:

  • Direct Inlining: The values are not wrapped in objects. An int[] holds raw 32-bit values directly adjacent to one another.
  • No Indirection: Reading an element only requires calculating the offset (header_size + index * element_size) and reading the value directly from that memory address.
  • Optimal Cache Locality: Because values are packed sequentially in memory, loading one element into the CPU cache automatically pulls adjacent elements into the L1/L2 cache lines, enabling fast sequential reads.
  • Minimal Overhead: The total memory consumed is simply the header size plus the raw size of all primitive elements, padded to the nearest multiple of 8 bytes.

Memory Layout of Reference Arrays

An array of reference types (such as Integer[], String[], or Object[]) does not store the actual objects inside the array boundary. Instead, the array itself stores only a contiguous list of references (memory pointers) pointing to objects located elsewhere on the heap.

Array Object:
[ Object Header (16 bytes) ] [ Ref 0 ] [ Ref 1 ] ... [ Ref N-1 ] [ Padding ]
                                  |         |
                                  v         v
                             [Object 0] [Object 1] (Scattered on heap)

Key characteristics include:

  • Pointer Storage: The array elements are 4-byte (with compressed oops) or 8-byte memory addresses.
  • Pointer Indirection: Accessing an element requires two memory lookups: first fetching the reference from the array, and then dereferencing that address to access the target object's fields.
  • Poor Cache Locality: The objects themselves may be scattered across non-contiguous memory regions on the heap. Accessing elements sequentially often causes CPU cache misses, commonly referred to as "pointer chasing."
  • High Memory Overhead: Memory is consumed twice: once for the array holding the references, and again for each individual object on the heap, each requiring its own object header, payload, and alignment padding.

Practical Impact: An Example Comparison

Consider storing 1,000 32-bit integers on a standard 64-bit JVM with compressed oops:

  • int[1000]:

    • Array header: 16 bytes
    • Payload: 1,000 × 4 bytes = 4,000 bytes
    • Padding: 0 bytes
    • Total: 4,016 bytes in a single contiguous block.

  • Integer[1000]:

    • Array header: 16 bytes
    • Reference array payload: 1,000 × 4 bytes = 4,000 bytes
    • Individual Integer objects: 1,000 instances × 16 bytes (12-byte header + 4-byte int payload) = 16,000 bytes
    • Total: ~20,016 bytes scattered across 1,001 distinct heap objects.

Primitive arrays provide a compact, contiguous memory footprint optimized for low overhead and hardware-level performance. Reference arrays introduce significant memory overhead and pointer indirection, trading raw efficiency for object-oriented polymorphism and nullable types.

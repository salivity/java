Using HTTP/2 and WebSocket with Java 11 HttpClient

Java 11 modernized network programming in the standard library by introducing the standardized java.net.http.HttpClient API, replacing the outdated and synchronous HttpURLConnection. This built-in client provides native, out-of-the-box support for both HTTP/2 and WebSocket protocols without requiring third-party libraries. By leveraging asynchronous programming patterns and reactive streams, the Java 11 HttpClient allows developers to build high-performance, non-blocking applications that can efficiently multiplex requests over HTTP/2 and maintain persistent, bidirectional WebSocket communication.

Native HTTP/2 Support

The HttpClient supports HTTP/2 as its default operational mode. When a request is initiated, the client attempts to negotiate an HTTP/2 connection with the server via Application-Layer Protocol Negotiation (ALPN) over TLS. If the server does not support HTTP/2, the client automatically and transparently falls back to HTTP/1.1.

Developers can explicitly configure or enforce the protocol version using the client builder:

HttpClient client = HttpClient.newBuilder()
    .version(HttpClient.Version.HTTP_2)
    .build();

HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://example.com"))
    .build();

HttpResponse<String> response = client.send(
    request, 
    HttpResponse.BodyHandlers.ofString()
);

System.out.println("Protocol version: " + response.version());

Key HTTP/2 capabilities handled internally by the client include:

  • Multiplexing: The client sends multiple concurrent bidirectional requests and responses over a single TCP connection as independent streams, eliminating the head-of-line blocking problem inherent in HTTP/1.1.
  • Header Compression (HPACK): Header data is automatically compressed and decompressed using HPACK, significantly reducing overhead on repetitive requests.
  • Server Push: The client supports HTTP/2 Server Push via HttpResponse.PushPromiseHandler, allowing applications to intercept and accept server-initiated resources before they are explicitly requested.

Native WebSocket Support

Unlike older Java networking utilities, Java 11 includes a dedicated WebSocket interface and builder accessible directly from an HttpClient instance. It facilitates full-duplex, event-driven communication over a single TCP connection without external dependencies.

To establish a WebSocket connection, use the client's newWebSocketBuilder() method, passing the target URI and an implementation of WebSocket.Listener:

HttpClient client = HttpClient.newHttpClient();

CompletableFuture<WebSocket> webSocketFuture = client.newWebSocketBuilder()
    .buildAsync(URI.create("wss://example.com/socket"), new WebSocket.Listener() {
        @Override
        public void onOpen(WebSocket webSocket) {
            System.out.println("WebSocket opened");
            webSocket.sendText("Hello Server", true);
            WebSocket.Listener.super.onOpen(webSocket);
        }

        @Override
        public CompletionStage<?> onText(WebSocket webSocket, CharSequence data, boolean last) {
            System.out.println("Received: " + data);
            return WebSocket.Listener.super.onText(webSocket, data, last);
        }

        @Override
        public CompletionStage<?> onClose(WebSocket webSocket, int statusCode, String reason) {
            System.out.println("Closed: " + reason);
            return WebSocket.Listener.super.onClose(webSocket, statusCode, reason);
        }
    });

WebSocket webSocket = webSocketFuture.join();

Key aspects of the WebSocket implementation include:

  • Asynchronous Lifecycle: Connection establishment is completely non-blocking, returning a CompletableFuture<WebSocket>.
  • Reactive Flow Control: The WebSocket.Listener interface provides callback hooks such as onOpen, onText, onBinary, onPing, onPong, and onClose. Message handling returns a CompletionStage<?>, giving consumers backpressure control to signal when they are ready to process subsequent frames.
  • Message Fragmentation: Methods like sendText(CharSequence message, boolean last) accept a boolean flag indicating whether the message is complete or part of a fragmented frame sequence.

By packaging robust HTTP/2 protocol negotiation and an asynchronous WebSocket API directly into the java.net.http package, Java 11 eliminated the need for external HTTP and WebSocket client libraries in modern enterprise applications.

Java Strategy Pattern: Swap Algorithms at Runtime

The Strategy pattern is a behavioral design pattern that enables selecting and swapping algorithms at runtime by encapsulating each algorithm into a separate class behind a common interface. By utilizing object composition and polymorphism instead of class inheritance, Java applications can dynamically alter an object's behavior during execution without modifying the client code that consumes it. This article explains how the Strategy pattern functions in Java, breaks down its core architectural components, and demonstrates how dynamic dispatch and setter injection facilitate seamless algorithm swapping.

Core Components of the Strategy Pattern

To achieve dynamic algorithm interchangeability, the Strategy pattern separates the execution context from the algorithm implementation using three primary components:

  1. Strategy Interface: A common Java interface that declares the method signatures shared by all supported algorithms. This defines the contract that the context uses to execute any algorithm.
  2. Concrete Strategies: Independent classes that implement the Strategy interface. Each class encapsulates a specific algorithm or operational behavior.
  3. Context: A class that maintains a reference to a Strategy object. The Context interacts exclusively with the Strategy interface, remaining completely decoupled from the specific implementation details of the concrete algorithms.

How Runtime Swapping Works

The mechanism that enables runtime swapping in Java relies on two fundamental object-oriented principles: polymorphism and composition over inheritance.

Instead of having a class inherit a fixed behavior or hardcoding business logic inside large conditional structures (if-else or switch statements), the Context class holds an instance variable typed to the Strategy interface.

At runtime, the Context can update this reference to point to any concrete implementation of that interface. When the Context invokes the algorithm method, Java's dynamic method dispatch automatically calls the implementation associated with the currently assigned object instance. This assignment can happen via constructor injection, dependency injection, or explicit setter methods.

Implementation Example in Java

The following code demonstrates a dynamic payment processing scenario where the checkout algorithm changes based on user selection during runtime.

1. The Strategy Interface

public interface PaymentStrategy {
    void pay(int amount);
}

2. Concrete Strategies

public class CreditCardPayment implements PaymentStrategy {
    private String cardNumber;

    public CreditCardPayment(String cardNumber) {
        this.cardNumber = cardNumber;
    }

    @Override
    public void pay(int amount) {
        System.out.println("Paid " + amount + " using Credit Card ending in " + cardNumber.substring(cardNumber.length() - 4));
    }
}

public class CryptoPayment implements PaymentStrategy {
    private String walletAddress;

    public CryptoPayment(String walletAddress) {
        this.walletAddress = walletAddress;
    }

    @Override
    public void pay(int amount) {
        System.out.println("Paid " + amount + " using Crypto Wallet: " + walletAddress);
    }
}

3. The Context Class

public class OrderContext {
    private PaymentStrategy paymentStrategy;

    // The strategy can be supplied initially
    public OrderContext(PaymentStrategy paymentStrategy) {
        this.paymentStrategy = paymentStrategy;
    }

    // The strategy can be swapped dynamically at runtime
    public void setPaymentStrategy(PaymentStrategy paymentStrategy) {
        this.paymentStrategy = paymentStrategy;
    }

    public void processOrder(int amount) {
        if (paymentStrategy == null) {
            throw new IllegalStateException("Payment strategy not set");
        }
        paymentStrategy.pay(amount);
    }
}

4. Executing Algorithm Swaps at Runtime

public class Main {
    public static void main(String[] args) {
        // Initial strategy: Credit Card
        OrderContext order = new OrderContext(new CreditCardPayment("1234567890123456"));
        order.processOrder(100);

        // Swap algorithm to Cryptocurrency at runtime
        order.setPaymentStrategy(new CryptoPayment("0x1A2B3C4D5E"));
        order.processOrder(250);
    }
}

Advantages of Runtime Swapping

  • Open/Closed Principle (OCP): New algorithms can be introduced by creating new classes that implement the interface without altering existing context or client code.
  • Elimination of Conditional Logic: Replaces complex branching logic with polymorphic method calls, making code cleaner and less error-prone.
  • Isolation of Concerns: The business logic of each algorithm is isolated in its own class, simplifying unit testing, debugging, and maintenance.

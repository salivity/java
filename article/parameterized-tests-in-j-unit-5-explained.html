Parameterized Tests in JUnit 5 Explained

JUnit 5 parameterized tests allow developers to execute a single test method multiple times using different datasets, eliminating code duplication and improving test coverage. By replacing the standard @Test annotation with @ParameterizedTest and pairing it with a data source annotation, JUnit's test runner automatically iterates over the provided inputs, injecting each element into the test method as arguments.

Core Dependency

To use parameterized tests, the junit-jupiter-params artifact must be included in your build configuration alongside the standard JUnit Jupiter engine.

Basic Mechanism

A parameterized test replaces the standard @Test annotation with @ParameterizedTest. The test method defines parameters in its signature, and JUnit injects values from a designated source into those parameters during each execution run.

import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.ValueSource;
import static org.junit.jupiter.api.Assertions.assertTrue;

class NumberTest {

    @ParameterizedTest
    @ValueSource(ints = {2, 4, 6, 8})
    void testIsEven(int number) {
        assertTrue(number % 2 == 0);
    }
}

In this example, testIsEven runs four separate times. If one assertion fails, JUnit marks only that specific invocation as failed while continuing to execute the remaining values.

Supplying Datasets

JUnit 5 provides several annotations to feed data into test methods, depending on the complexity and structure of the input:

1. @ValueSource

The simplest provider, @ValueSource, accepts a single array of literal values. Supported types include primitives (int, long, double, etc.), String, and Class. It is ideal for single-argument tests.

2. @CsvSource and @CsvFileSource

When a test method requires multiple arguments per run, @CsvSource allows you to express records as comma-separated strings.

import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;
import static org.junit.jupiter.api.Assertions.assertEquals;

class CalculationTest {

    @ParameterizedTest
    @CsvSource({
        "1, 2, 3",
        "5, 5, 10",
        "-1, 3, 2"
    })
    void testAddition(int a, int b, int expected) {
        assertEquals(expected, a + b);
    }
}

For large datasets, @CsvFileSource reads input values directly from external CSV files located in the project's classpath.

3. @MethodSource

For complex objects, collections, or dynamically generated inputs, @MethodSource references an external factory method that returns a Stream, Iterable, Iterator, or array of Arguments.

import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.Arguments;
import org.junit.jupiter.params.provider.MethodSource;
import java.util.stream.Stream;
import static org.junit.jupiter.api.Assertions.assertNotNull;

class UserTest {

    static Stream<Arguments> userProvider() {
        return Stream.of(
            Arguments.of("Alice", 30),
            Arguments.of("Bob", 25)
        );
    }

    @ParameterizedTest
    @MethodSource("userProvider")
    void testUserData(String name, int age) {
        assertNotNull(name);
        assertTrue(age > 0);
    }
}

4. @EnumSource

@EnumSource provides an easy way to run a test method against constants from a Java enum, with options to filter or include specific values.

Test Execution Lifecycle

During execution, JUnit 5 treats each parameter set as an independent test invocation. Test lifecycles, including @BeforeEach and @AfterEach lifecycle callbacks, execute before and after every individual parameter iteration rather than once for the entire method. Failure reports in IDEs and build tools display each dataset with a unique index and argument label, pinpointing precisely which inputs caused an assertion error.

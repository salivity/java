Parent and Child Constructor Order in Java

When instantiating a child class in Java, the runtime environment follows a strict top-down initialization process where the parent (superclass) constructor always executes before the child (subclass) constructor. This article explains the precise execution sequence during Java object creation, the mechanics of implicit and explicit super() calls, and the full step-by-step lifecycle including instance variable initialization and static blocks.

The Core Rule: Parent First, Child Second

In Java inheritance, an object of a derived class contains all the fields and behaviors inherited from its base class. To ensure that the inherited state is properly configured before the subclass attempts to access or modify it, the parent class constructor must execute first.

Even if you instantiate only the child class directly:

Child obj = new Child();

The runtime will navigate up the inheritance hierarchy to the topmost class (eventually java.lang.Object) and execute constructors going downward toward the instantiated class.

The Role of super()

The delegation from child to parent occurs via the super() statement:

  • Implicit super(): If you do not explicitly invoke a parent constructor in the first line of the child constructor, the Java compiler automatically inserts a call to super() (the parameterless constructor of the superclass).
  • Explicit super(): If the parent class does not have a default, no-argument constructor, you must explicitly invoke an available parent constructor using super(arguments) as the very first statement in the child constructor. Failing to do so causes a compilation error.
  • this() Chaining: If a constructor calls another overloaded constructor in the same class using this(), the call to super() is deferred until the final target constructor in the chain is reached.

The Complete Step-by-Step Instantiation Order

When a child class is loaded and instantiated for the first time, the complete execution sequence occurs in the following order:

  1. Static Initializers and Static Fields:

    • Executed once per class loader session.
    • Parent static members and static { ... } blocks run first.
    • Child static members and static { ... } blocks run second.

  2. Parent Instance Members and Blocks:

    • Parent instance variable declarations and instance initializer blocks { ... } run in the order they appear in the source code.

  3. Parent Constructor:

    • The body of the parent constructor executes to completion.

  4. Child Instance Members and Blocks:

    • Child instance variable declarations and instance initializer blocks { ... } run in the order they appear.

  5. Child Constructor:

    • The body of the child constructor executes to completion.

Code Demonstration

Consider the following example:

class Parent {
    // 1. Parent instance variable/block
    int parentValue = 10;
    {
        System.out.println("Parent instance block");
    }

    // 2. Parent constructor
    Parent() {
        System.out.println("Parent constructor executed. Value: " + parentValue);
    }
}

class Child extends Parent {
    // 3. Child instance variable/block
    int childValue = 20;
    {
        System.out.println("Child instance block");
    }

    // 4. Child constructor
    Child() {
        // Implicit super() is called here before anything below
        System.out.println("Child constructor executed. Value: " + childValue);
    }
}

public class Main {
    public static void main(String[] args) {
        new Child();
    }
}

Output:

Parent instance block
Parent constructor executed. Value: 10
Child instance block
Child constructor executed. Value: 20

Why This Order Is Crucial

This execution model enforces object safety. If the child constructor were permitted to run first, any subclass logic that accessed inherited fields or invoked inherited methods would encounter an uninitialized parent state, leading to inconsistent object behavior and unpredictable runtime errors.

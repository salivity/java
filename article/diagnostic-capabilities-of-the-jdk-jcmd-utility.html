Diagnostic Capabilities of the JDK jcmd Utility

The jcmd utility is a lightweight, command-line diagnostic tool included in the Java Development Kit (JDK) designed to troubleshoot, profile, and monitor running Java Virtual Machine (JVM) processes. This article outlines the primary diagnostic capabilities offered by jcmd, detailing how it facilitates thread dump generation, heap and native memory inspection, garbage collection control, and Java Flight Recorder management without requiring application restarts.

Process Discovery and Command Inspection

Running jcmd without arguments lists all active Java process identifiers (PIDs) alongside their main class names. Once a target PID is identified, executing jcmd <PID> help outputs all diagnostic commands supported by that specific JVM instance. This ensures compatibility across different Java versions, as commands can vary depending on the runtime environment.

Thread Diagnostics

One of the most frequent uses of jcmd is generating thread dumps using the Thread.print command. This produces a snapshot of all active threads, their execution states (RUNNABLE, BLOCKED, WAITING), call stacks, and synchronized locks held or requested. It is essential for diagnosing deadlocks, thread contention, and CPU-intensive operations in production with minimal overhead.

Heap and Garbage Collection Analysis

jcmd provides several commands to inspect and manage heap memory:

  • GC.class_histogram: Displays a breakdown of loaded classes, the number of instantiated objects per class, and the total memory consumed. This is useful for identifying memory leaks and high-allocation objects without incurring the pause times of a full heap dump.
  • GC.heap_dump: Writes a complete HPROF-formatted heap dump to disk for in-depth offline analysis using tools such as Eclipse Memory Analyzer (MAT) or VisualVM.
  • GC.run: Triggers a full garbage collection cycle, primarily used in testing environments to evaluate reclamation behavior.

Native Memory Tracking (NMT)

When a JVM is launched with the -XX:NativeMemoryTracking=summary or -XX:NativeMemoryTracking=detail flag, jcmd can monitor memory consumed outside the Java heap.

The VM.native_memory command allows engineers to track native memory allocated by the metaspace, thread stacks, internal garbage collectors, and JIT compilers. By using baseline markers (VM.native_memory baseline followed by VM.native_memory detail.diff), developers can identify native memory leaks that traditional heap dumps do not capture.

Java Flight Recorder (JFR) Control

jcmd acts as the primary command-line interface for controlling Java Flight Recorder on running applications. It allows users to start, stop, check, and dump profiling sessions on demand:

  • JFR.start: Begins a continuous or duration-based recording with specified settings (e.g., profiling or default template).
  • JFR.check: Displays active recordings and their current status.
  • JFR.dump: Writes collected event data to an .jfr file for analysis in JDK Mission Control.
  • JFR.stop: Ends an active recording session.

Metaspace and Class Loader Inspection

The utility offers specific insights into class metadata and class loaders:

  • VM.classloader_stats: Details class loader hierarchies, including the number of classes loaded, parent-child relationships, and memory overhead, which aids in detecting class loader leaks.
  • VM.metaspace: Provides detailed reporting on metaspace usage, chunk allocation, and fragmentation.

JVM Configuration and Flag Management

jcmd allows operators to query and dynamically modify runtime parameters:

  • VM.flags: Prints all JVM flags currently in effect, highlighting which values were set explicitly versus those selected by ergonomics.
  • VM.system_properties: Dumps all active Java system properties.
  • VM.uptime: Shows how long the target JVM process has been running.
  • VM.set_flag: Modifies manageable JVM flags dynamically without requiring a process restart.

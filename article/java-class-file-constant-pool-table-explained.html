Java Class File Constant Pool Table Explained

The constant pool table is a foundational component of the compiled Java class file format, serving as an indexed symbol table that stores numeric literals, string constants, class and interface names, and method and field references. Residing immediately after the version metadata in a .class file, this table acts as a central repository that bytecode instructions reference by index, drastically reducing the binary size and enabling the dynamic linking mechanism of the Java Virtual Machine (JVM).

Where the Constant Pool Resides

A compiled .class file is a strictly ordered sequence of binary data. The constant pool table occupies a fixed position near the very beginning of this binary layout:

  1. Magic Number (4 bytes): Always 0xCAFEBABE, identifying the file as valid Java bytecode.
  2. Minor Version (2 bytes): The minor version of the class file format.
  3. Major Version (2 bytes): The major version (e.g., 65 for Java 21).
  4. constant_pool_count (2 bytes): An unsigned 16-bit integer indicating the number of entries in the constant pool table plus one.
  5. constant_pool[] (Variable size): The constant pool table itself.

Immediately following the major version bytes, the JVM reads the constant_pool_count. The actual table begins directly after this count and precedes the access flags, this_class reference, and super_class reference.

Structure of the Constant Pool Table

The constant pool table is an array of variable-length structures known as cp_info. Unlike typical zero-indexed arrays in Java, the constant pool is 1-indexed (indices run from 1 to constant_pool_count - 1). Index 0 is reserved for internal JVM use and represents an invalid or null reference.

Each entry in the table starts with a 1-byte tag that defines the entry type:

  • Literals: Store raw constant values, such as CONSTANT_Integer, CONSTANT_Float, CONSTANT_Long, CONSTANT_Double, and CONSTANT_Utf8 (which holds raw character strings).
  • Symbolic References: Structures that point to other constant pool entries to represent program entities without hardcoding memory addresses. Examples include:
    • CONSTANT_Class: References a CONSTANT_Utf8 holding the fully qualified class name.
    • CONSTANT_Fieldref: References class and name-and-type entries for a specific field.
    • CONSTANT_Methodref and CONSTANT_InterfaceMethodref: Reference class and name-and-type entries for methods.
    • CONSTANT_NameAndType: References two CONSTANT_Utf8 entries representing a field or method's name and its type descriptor.
    • CONSTANT_MethodHandle and CONSTANT_InvokeDynamic: Support dynamic language features and lambda expressions introduced in Java 7 and 8.

Note that 64-bit constants (CONSTANT_Long and CONSTANT_Double) occupy two consecutive entries in the table, meaning the index following a long or double entry is skipped.

How the JVM Uses the Constant Pool

Rather than inlining extensive strings, signatures, and symbol names directly into executable instructions, bytecode instructions use lightweight index pointers to reference entries in the constant pool.

For instance, the instruction ldc #4 tells the JVM to load the constant located at index 4 of the constant pool onto the operand stack. Similarly, method invocation instructions like invokevirtual #12 instruct the JVM to look up index 12 to resolve the target method's name, class, and descriptor. When the JVM loads the class, it uses these symbolic entries to resolve references into actual direct memory pointers during the linking and resolution phases.

Java NIO Buffer flip vs clear vs rewind

Java NIO buffers rely on internal state variables—primarily position, limit, and capacity—to manage sequential data processing without reallocating memory. The flip(), clear(), and rewind() methods are essential state-management utilities that alter these tracking pointers. Understanding how these methods manipulate the buffer's position and limit is critical for correctly transitioning between reading, writing, and re-reading data in Java NIO channels.

Buffer State Variables

To understand these methods, you must understand the two primary pointers:

  • Position: The index of the next element to be read or written.
  • Limit: The first element that should not be read or written.
  • Capacity: The total size of the allocated memory block.

The flip() Method

The flip() method switches a buffer from writing mode to reading mode.

When you write data into a buffer (via a Channel.read(buffer) or manual put() operations), the position advances forward while the limit stays at capacity. Once writing is finished, you must flip the buffer to read that data back out.

What flip() does:

  1. Sets limit to the current position.
  2. Resets position to 0.
  3. Discards any previously set mark.
// Example: Writing data, then reading it
ByteBuffer buffer = ByteBuffer.allocate(1024);
buffer.put((byte) 10);
buffer.put((byte) 20);

buffer.flip(); // limit becomes 2, position becomes 0

byte a = buffer.get(); // reads 10, position becomes 1
byte b = buffer.get(); // reads 20, position becomes 2

The clear() Method

The clear() method prepares a buffer for a new cycle of writing.

Contrary to its name, clear() does not wipe or zero out the underlying data array. Instead, it resets the internal indices so you can overwrite existing data from the start of the buffer.

What clear() does:

  1. Sets position to 0.
  2. Sets limit to capacity.
  3. Discards any previously set mark.
// Example: Resetting for new writes
buffer.clear(); // position becomes 0, limit becomes 1024
buffer.put((byte) 99); // overwrites the first byte

Use clear() when you have fully processed the data in the buffer and are ready to fill it again. If you only partially read the buffer and want to keep unread data before writing again, use compact() instead.

The rewind() Method

The rewind() method prepares a buffer for re-reading the same data.

If you have already read data from a buffer but need to process it a second time—such as verifying a checksum or writing to multiple channels—rewind() resets the read position without losing track of where the data ends.

What rewind() does:

  1. Sets position to 0.
  2. Leaves limit unchanged.
  3. Discards any previously set mark.
// Example: Re-reading data
buffer.rewind(); // position resets to 0; limit remains untouched

while (buffer.hasRemaining()) {
    System.out.println(buffer.get());
}

Quick Comparison

Method Position Limit Typical Use Case
flip() 0 Previous position Switching from writing/filling to reading/draining.
clear() 0 capacity Resetting the buffer to begin writing new data from scratch.
rewind() 0 Unchanged Re-reading or re-writing the same data segment.

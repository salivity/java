Java Memento Pattern for Safe State Rollback

The Memento pattern is a behavioral design pattern that allows you to capture and externalize an object's internal state without violating encapsulation, making it possible to restore the object to this state later. This article explores how the Memento pattern functions, its primary structural components, and how to implement a safe, robust state rollback (undo/redo) mechanism in Java using private inner classes and narrow interfaces.

Core Components of the Memento Pattern

The pattern decouples the state management logic from the business logic by distributing responsibilities among three actors:

  1. Originator: The object that holds the active state. It creates a snapshot of its current state in a Memento and uses a Memento to revert to a previous state.
  2. Memento: An immutable object that stores the Originator's state. It provides a "wide" interface to the Originator (allowing full access to state data) and a "narrow" interface to external objects (hiding internal state).
  3. Caretaker: The object responsible for holding the Mementos (often in a stack or list for history tracking). It never operates on or inspects the contents of a Memento.

Ensuring Safety and Encapsulation in Java

A common vulnerability in rollback mechanisms is exposing mutable state to outside classes. If external objects modify a state snapshot, rollback operations become unpredictable.

In Java, encapsulation safety is best achieved by:

  • Making the Memento immutable (final fields, no setters).
  • Defining the concrete Memento as a private static inner class within the Originator, exposing only a public marker interface to the Caretaker.

Java Implementation

1. The Memento Interface

A narrow interface with no methods (a marker interface) prevents the Caretaker from accessing state fields.

public interface Memento {
    // Narrow interface exposed to the Caretaker
}

2. The Originator

The TextEditor creates and consumes mementos. Its internal state is stored in a private inner class that implements the Memento interface.

public class TextEditor {
    private String content;

    public void setContent(String content) {
        this.content = content;
    }

    public String getContent() {
        return content;
    }

    // Creates a snapshot of current state
    public Memento save() {
        return new EditorMemento(this.content);
    }

    // Restores state from a snapshot
    public void restore(Memento memento) {
        if (!(memento instanceof EditorMemento)) {
            throw new IllegalArgumentException("Unknown memento implementation.");
        }
        EditorMemento state = (EditorMemento) memento;
        this.content = state.getContent();
    }

    // Wide interface: accessible only within TextEditor
    private static class EditorMemento implements Memento {
        private final String content;

        private EditorMemento(String content) {
            this.content = content;
        }

        private String getContent() {
            return content;
        }
    }
}

3. The Caretaker

The History class manages the lifecycle of snapshots using a stack without inspecting the content stored within them.

import java.util.ArrayDeque;
import java.util.Deque;

public class History {
    private final Deque<Memento> history = new ArrayDeque<>();

    public void push(Memento memento) {
        history.push(memento);
    }

    public Memento pop() {
        if (history.isEmpty()) {
            return null;
        }
        return history.pop();
    }
}

4. Executing the Rollback

public class Main {
    public static void main(String[] args) {
        TextEditor editor = new TextEditor();
        History history = new History();

        // Initial state
        editor.setContent("Version 1");
        history.push(editor.save());

        // State update
        editor.setContent("Version 2");
        history.push(editor.save());

        // Unsaved change
        editor.setContent("Version 3 (Draft)");
        System.out.println("Current: " + editor.getContent()); // Version 3 (Draft)

        // Rollback to last saved state
        editor.restore(history.pop());
        System.out.println("Rollback 1: " + editor.getContent()); // Version 2

        // Rollback to original state
        editor.restore(history.pop());
        System.out.println("Rollback 2: " + editor.getContent()); // Version 1
    }
}

Considerations and Trade-Offs

  • Memory Consumption: If the Originator maintains a large memory footprint or state changes are frequent, storing full snapshots can quickly exhaust the Java Virtual Machine (JVM) heap. In high-throughput systems, using delta-based compression (storing only state differences) is preferred.
  • Deep vs. Shallow Copies: If the Originator's state includes complex reference types (such as collections or nested objects), the Memento must perform deep copies during creation to prevent post-snapshot modifications to external references.

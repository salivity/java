How Project Valhalla Brings Value Objects to Java

Project Valhalla is an OpenJDK initiative designed to modernize the Java memory model by introducing value objects, bridging the long-standing divide between primitive types and reference objects. This article explores how Valhalla eliminates object identity to enable flat, cache-friendly data layouts, the architectural mechanisms behind value classes, and how these changes dramatically enhance Java's runtime performance without sacrificing object-oriented programming abstractions.

The Problem: Java's Identity Overhead

Java has traditionally maintained a strict dichotomy between primitive types (int, double, etc.) and reference objects (Object). While primitives are small, dense, and stored directly on the stack or inline within arrays, reference objects carry significant overhead:

  • Object Headers: Every standard object on the heap requires metadata (typically 8 to 16 bytes for 64-bit systems) to manage garbage collection, locking, and type identification.
  • Pointer Indirection: Objects are accessed via references (pointers), causing CPU cache misses when traversing arrays of objects.
  • Heap Allocation: Ordinary objects require heap management and garbage collection cycles, even for small composite data structures like complex numbers or points.

Discarding Object Identity

Valhalla’s guiding philosophy is "Codes like a class, works like an int." It achieves this by stripping away object identity.

Standard Java objects rely on identity for:

  • Reference equality (== checking if two references point to the same memory location).
  • Mutability (updating state within a persistent memory address).
  • Synchronization (using the object's built-in monitor for thread locking).

Valhalla introduces value class declarations. Instances of value classes lack an identity: they are immutable, cannot be locked upon, and compare via state (field values) rather than memory addresses. Because identity is gone, the Java Virtual Machine (JVM) does not need to guarantee a fixed memory location or attach an object header.

Flat Memory Layout and Inlining

Without the need for identity headers or pointer stability, the JVM can optimize value objects directly into the execution pipeline:

  • Flattened Arrays: Instead of an array of references pointing to scattered objects across the heap, an array of value objects is stored as a contiguous block of field data in memory. This eliminates indirection and maximizes CPU cache line efficiency.
  • Calling Convention Optimizations: Small value objects can be decomposed directly into CPU registers during method calls, completely bypassing stack-frame allocation.
  • Zero GC Overhead: When value objects behave like scalar primitives, they are treated as pure data values, drastically reducing garbage collector pressure.

The Spectrum: Value and Primitive Classes

Valhalla structures this transition along clear JVM classifications:

  1. Identity Classes: Traditional Java classes (class) that retain identity, locks, and reference semantics.
  2. Value Classes: Declared using the value modifier. They are identity-free but remain reference-compatible (they support nullability and behave safely across legacy APIs).
  3. Primitive Value Classes: A further specialization where types can declare themselves non-nullable and zero-initialized. These can be fully flattened in memory without even needing a reference representation.

Unifying Generics with Universal Types

A critical goal of Project Valhalla is universal generics. Currently, generic types rely on type erasure to java.lang.Object, forcing primitives to be boxed into wrapper types (like Integer for int).

Valhalla paves the way for specialized generics, allowing collections such as List<Point> or Map<int, String> to run with zero boxing overhead. The compiler generates code that accommodates both reference types and flattened value representations under a single unified type system.

Thread.interrupt vs Thread.interrupted in Java

Handling thread interruptions properly is a fundamental aspect of writing robust multithreaded applications in Java. Java uses a cooperative interruption mechanism where threads communicate cancellation or pause requests via an internal boolean flag known as the interrupt status. This article explains the core differences between Thread.interrupt() and Thread.interrupted(), detailing how one serves as an action to signal a thread, while the other serves as a state check with a built-in side effect.

What is Thread.interrupt()?

Thread.interrupt() is an instance method used to send an interruption signal to a specific thread. Calling this method sets the target thread's interrupt status flag to true.

Key characteristics of interrupt() include:

  • Target-specific: It is invoked on a specific Thread instance (for example, workerThread.interrupt()).
  • Non-blocking signal: If the target thread is running normal code, its interrupted status flag is simply set to true. The thread is responsible for actively checking this flag to stop its work.
  • Wakes up blocked threads: If the target thread is currently blocked in methods like Thread.sleep(), Object.wait(), or Thread.join(), the thread wakes up immediately, clears its interrupted status (sets it back to false), and throws an InterruptedException.

What is Thread.interrupted()?

Thread.interrupted() is a static method used to check whether the currently executing thread has been interrupted.

Key characteristics of interrupted() include:

  • Applies only to the current thread: Because it is a static method, it always queries the thread executing the call, equivalent to inspecting Thread.currentThread().
  • Clears the interrupted status: This is its most critical feature. When Thread.interrupted() returns true, it immediately resets the interrupted status of the current thread to false. If you call it twice consecutively, the second call will almost certainly return false (unless another interrupt occurred in between).

Comparison: The Key Differences

Feature Thread.interrupt() Thread.interrupted()
Method Type Instance method Static method
Target Any specific Thread object The currently running thread
Primary Purpose Action: Triggers an interrupt request Check: Queries the interrupt status
Effect on Status Flag Sets the flag to true Reads the flag and resets it to false

Checking Status Without Clearing It: isInterrupted()

Because Thread.interrupted() clears the interrupted flag, calling it can lead to bugs if your application logic relies on preserving the interrupted state for callers higher up the call stack.

If you need to check whether a thread is interrupted without clearing its status, Java provides another instance method: isInterrupted().

// Checks the status without clearing the flag
if (Thread.currentThread().isInterrupted()) {
    // The flag remains true after this check
}

Summary of Usage

Use thread.interrupt() when you want to signal another thread (or the current thread) that it should stop what it is doing. Use Thread.interrupted() inside a task loop when you want to check if the current thread was asked to stop and simultaneously clear the flag so the thread can reset its state or continue running cleanly. If you only want to inspect the flag without modifying it, use Thread.currentThread().isInterrupted().

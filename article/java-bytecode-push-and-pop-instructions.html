Java Bytecode Push and Pop Instructions

The Java Virtual Machine (JVM) is a stack-based execution engine that uses an operand stack to evaluate expressions, pass method arguments, and store return values. This article outlines the standard bytecode instructions responsible for pushing values onto and popping values off the operand stack, categorized by their specific behavior, operand types, and memory models.

Pushing Constants to the Operand Stack

Constant push instructions load hardcoded literal values or pool references directly onto the top of the stack.

1. Inherent Constant Instructions

These instructions embed the value directly within the opcode itself without requiring extra operand bytes:

  • aconst_null: Pushes a null object reference.
  • iconst_m1 to iconst_5: Pushes integer constants -1, 0, 1, 2, 3, 4, or 5.
  • lconst_0, lconst_1: Pushes 64-bit long values 0L or 1L (occupies two stack slots).
  • fconst_0, fconst_1, fconst_2: Pushes 32-bit float values 0.0f, 1.0f, or 2.0f.
  • dconst_0, dconst_1: Pushes 64-bit double values 0.0d or 1.0d (occupies two stack slots).

2. Immediate Byte and Short Instructions

For small numbers outside the inherent range, the JVM provides instructions that read following bytes:

  • bipush <byte>: Takes an 8-bit signed byte, sign-extends it to a 32-bit integer, and pushes it onto the stack.
  • sipush <short>: Takes a 16-bit signed short, sign-extends it to a 32-bit integer, and pushes it onto the stack.

3. Constant Pool Push Instructions (ldc)

For arbitrary constants, strings, floating-point numbers, and class references, instructions pull data from the runtime constant pool:

  • ldc <index>: Pushes an 8-bit indexed item (e.g., an int, float, string literal, or class reference).
  • ldc_w <index>: Pushes an item from a wider 16-bit constant pool index.
  • ldc2_w <index>: Pushes a 64-bit constant (long or double) using a 16-bit index.

Pushing Local Variables to the Stack (Load Instructions)

Values stored in local variable slots are transferred to the operand stack via load instructions.

  • iload / iload_<n> (where n is 0 through 3): Pushes an integer or boolean/byte/char/short value from a local variable.
  • lload / lload_<n>: Pushes a 64-bit long from a local variable.
  • fload / fload_<n>: Pushes a 32-bit float from a local variable.
  • dload / dload_<n>: Pushes a 64-bit double from a local variable.
  • aload / aload_<n>: Pushes a reference type from a local variable.

Popping from the Operand Stack

Popping instructions remove values from the top of the stack. Depending on the opcode, values can be discarded entirely or transferred into local variables.

1. Pure Discard Instructions

These instructions remove entries from the stack without writing them to memory:

  • pop: Removes the top 32-bit value from the stack (Category 1 computational types: int, float, reference).
  • pop2: Pops either:
    • Two 32-bit values (Category 1).
    • One 64-bit value (Category 2 computational types: long, double).

2. Store Instructions (Pop to Local Variable)

Store instructions pop the top value off the stack and write it into a specific local variable index:

  • istore / istore_<n>: Pops an integer from the stack and stores it into a local variable.
  • lstore / lstore_<n>: Pops a long value from the stack.
  • fstore / fstore_<n>: Pops a float value from the stack.
  • dstore / dstore_<n>: Pops a double value from the stack.
  • astore / astore_<n>: Pops an object reference from the stack.

Stack Manipulation: Duplicate and Swap

In addition to pure push and pop operations, the JVM defines instructions to reorder and duplicate values already present on the operand stack:

  • dup: Duplicates the top 32-bit value and pushes it back onto the stack.
  • dup2: Duplicates the top one 64-bit or two 32-bit values.
  • dup_x1 / dup_x2: Duplicates the top value and inserts it beneath one or two existing items.
  • dup2_x1 / dup2_x2: Duplicates top Category 2 values and inserts them lower in the stack.
  • swap: Swaps the top two 32-bit values on the stack.

How Jackson and Gson Serialize Java Object Graphs

This article provides an in-depth look at how popular Java JSON processing libraries, primarily Jackson and Gson, convert complex in-memory Java object graphs into JSON strings and reconstruct them back into objects. You will learn the mechanics behind reflection, tree-traversal algorithms, type token handling for generics, circular reference resolution, and how these libraries optimize performance through streaming and caching.

The Core Mechanism: Reflection and Metadata

At the core of both Jackson and Gson is the Java Reflection API. When an object is passed to a serializer, the library inspects the class structure to discover its fields, accessor methods (getters/setters), constructors, and annotations.

To avoid the severe performance penalties associated with repeated reflective lookups, both libraries build and cache internal metadata models.

  • Jackson constructs a POJOPropertiesCollector and caches the class's BeanDescription inside a SerializerCache and DeserializerCache.
  • Gson constructs and caches TypeAdapter instances based on TypeToken representations of classes.

The Serialization Process (Object Graph to JSON)

Serialization is a depth-first traversal of a Java object graph, recursively translating references into nested JSON structures.

  1. Root Inspection: The serializer checks the runtime type of the root object and looks up its corresponding serializer or adapter.
  2. Field Traversal: The library iterates over each serializable field. It checks inclusion rules, ignoring fields that are marked transient, configured to be excluded, or evaluated as null (if null-skipping is enabled).
  3. Primitive and Scalar Conversion: Primitive types, wrapper classes, strings, dates, and enums are written directly to an underlying token stream (such as Jackson’s JsonGenerator or Gson’s JsonWriter).
  4. Nested Objects and Collections: When a field contains a complex object, an array, or a Collection, the serializer halts execution on the current object and recursively invokes serialization on the child reference. Collections and arrays produce opening and closing JSON brackets ([ and ]), while objects produce braces ({ and }).

Handling Cyclic Dependencies

In bidirectional relationships (for example, a User has many Orders, and each Order references its User), a naive recursive descent leads to a StackOverflowError.

  • Jackson handles cycles through annotations:
    • @JsonManagedReference and @JsonBackReference: The forward reference is serialized normally, while the backward reference is omitted.
    • @JsonIdentityInfo: Serializes the complete object on first encounter and serializes only an identifier (such as an ID) on subsequent encounters.
  • Gson does not natively resolve cyclical graphs automatically. Circular references cause a StackOverflowError unless an excluded strategy or a custom TypeAdapter is implemented.

The Deserialization Process (JSON to Object Graph)

Deserialization reverses this operation, transforming a linear stream of JSON tokens back into a connected in-memory graph.

  1. Tokenization: A low-level streaming parser (Jackson's JsonParser or Gson's JsonReader) processes raw bytes or characters into discrete syntactic tokens: START_OBJECT, FIELD_NAME, VALUE_STRING, END_OBJECT, etc.
  2. Instance Creation:
    • Jackson searches for a default no-argument constructor or a constructor/static factory method marked with @JsonCreator.
    • Gson attempts to use a no-argument constructor. If none exists, it uses internal JVM mechanisms (such as sun.misc.Unsafe.allocateInstance) to instantiate the class without invoking any constructor.
  3. Field Matching and Type Coercion: As field names are read, the library matches them against cached property metadata. Values are coerced into their target Java types (e.g., parsing an ISO string to a LocalDate or an integer into a Long).
  4. Handling Generics: Java's type erasure removes generic parameter details at runtime. To map nested structures like List<MyEntity>, libraries rely on:
    • Gson's TypeToken: Captures generic types via an anonymous inner class (new TypeToken<List<MyEntity>>(){}.getType()).
    • Jackson's TypeReference or JavaType: Reconstructs the full generic hierarchy for parameterized types.
  5. Polymorphic Deserialization: When handling abstract classes or interfaces, Jackson uses type identifiers embedded within the JSON (configured via @JsonTypeInfo and @JsonSubTypes) to determine the exact concrete subclass to instantiate. Gson achieves this using custom JsonDeserializer implementations or the RuntimeTypeAdapterFactory utility.

Java Source File Naming for Public Classes

In Java, file naming is not merely a stylistic preference but a strict compiler-enforced requirement when dealing with public top-level classes. This article outlines the precise rules and language conventions that govern how source files containing public classes must be named, the reasons behind these requirements, and the consequences of violating them.

The Exact Match Rule

The primary rule defined by the Java Language Specification (JLS) states that if a .java source file contains a public top-level class, interface, enum, or record, the base name of the source file must match the name of that public declaration exactly, followed by the .java extension.

For example, if you declare:

public class CustomerOrder {
    // Class body
}

The file containing this declaration must be named CustomerOrder.java. If the file is named anything else, such as Order.java or customerorder.java, the Java compiler (javac) will reject the code and throw a compilation error indicating that the public type must be defined in its own file.

Case Sensitivity

Java is a case-sensitive language, and this sensitivity extends directly to source file names across all operating systems.

  • The capitalization of the file name must correspond character-for-character with the class identifier.
  • While case-insensitive file systems (such as default installations of Windows and macOS) might allow the file to be saved with mismatched casing, the Java compiler will flag an error or produce unexpected runtime behavior when resolving dependencies.
  • To adhere to Java naming conventions, top-level classes must be written in PascalCase (UpperCamelCase), meaning the source file will also naturally follow PascalCase (e.g., HttpRequestHandler.java).

The Single Public Class Constraint

A single Java compilation unit (a .java file) can contain at most one public top-level type.

  • You cannot define multiple public classes at the top level within the same file.
  • A file may contain additional non-public (package-private) top-level classes, but the file name must still exclusively reflect the single public class.
  • If a file contains no public top-level classes, it can technically be named anything valid by the host file system (ending in .java), though naming it after the primary non-public class is standard practice.

Why This Rule Exists

This strict naming convention allows the Java compiler and the Java Virtual Machine (JVM) class loader to locate compiled .class files and dependencies efficiently. Because the package structure maps to directories and the public class name maps directly to the file name, the compiler can resolve types on the classpath without having to scan the contents of every file in a directory.

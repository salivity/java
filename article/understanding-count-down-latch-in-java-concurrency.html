Understanding CountDownLatch in Java Concurrency

This article provides an overview of the CountDownLatch class in Java, explaining its core purpose, internal mechanics, and practical applications in multithreaded programming. You will learn how this synchronization utility coordinates thread execution by blocking one or more threads until a set of operations completes, along with common design patterns such as start signals and completion barriers.

What Is a CountDownLatch?

Introduced in Java 5 as part of the java.util.concurrent package, CountDownLatch is a concurrency utility designed to synchronize threads. Its primary purpose is to enable one or more threads to wait until a specified number of operations being executed in other threads have completed.

A CountDownLatch is initialized with a positive integer counter. Calling threads can pause their execution until this counter reaches zero.

How CountDownLatch Works

The operation of CountDownLatch revolves around two primary methods:

  1. await(): Causes the current thread to block until the latch counter reaches zero due to invocations of the countDown() method. Overloaded variants allow specifying a timeout to prevent indefinite blocking.
  2. countDown(): Decrements the count of the latch by one. When the count reaches zero, all waiting threads are released, and any subsequent calls to await() return immediately without blocking.

The counter cannot be reset. Once the count reaches zero, the latch is considered open and cannot be reused. If you need a reusable synchronization barrier, Java provides CyclicBarrier.

Primary Use Cases

1. Waiting for Dependent Services to Initialize

A common application is ensuring that a main application thread does not proceed until several background services or worker threads have finished their startup routines.

  • The latch is initialized with the number of services (e.g., new CountDownLatch(3)).
  • Each service performs its initialization in a separate thread and calls countDown() upon completion.
  • The main thread calls await(), unblocking only after all three services are fully running.

2. Dividing a Task Across Multiple Worker Threads

When processing large datasets or parallel computations, a master task may divide the workload among several worker threads.

  • A latch is initialized with the count of worker threads.
  • Each worker processes its partition of the data and invokes countDown().
  • The orchestrating thread calls await() to pause execution until all workers have finished before aggregating the results.

3. Simultaneous Execution (The "Start Gate")

A CountDownLatch initialized with a count of 1 can serve as an on/off gate to achieve maximum parallelism.

  • Multiple worker threads call await() on the same latch with a count of 1.
  • When the coordinator thread is ready, it invokes countDown().
  • All waiting worker threads are released simultaneously, allowing them to begin execution at the exact same moment.

Key Methods Summary

  • CountDownLatch(int count): Constructs a latch initialized with the given count.
  • void await(): Causes the current thread to wait until the latch has counted down to zero, unless the thread is interrupted.
  • boolean await(long timeout, TimeUnit unit): Causes the current thread to wait until the latch counts down to zero, the timeout elapses, or the thread is interrupted.
  • void countDown(): Decrements the count of the latch, releasing all waiting threads if the count reaches zero.
  • long getCount(): Returns the current count, primarily useful for debugging or monitoring.

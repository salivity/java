How to Prevent ConcurrentModificationException in Java

A ConcurrentModificationException in Java occurs when a collection is modified while it is being traversed using a fail-fast iterator, whether in a single-threaded or multi-threaded environment. This article explores why this runtime exception happens and provides practical, effective techniques to prevent it—ranging from using the built-in Iterator.remove() method and Java 8 predicates to leveraging concurrent collection classes and defensive copying.

Understanding the Root Cause

Standard Java collections (such as ArrayList, HashSet, and HashMap) use fail-fast iterators. These iterators maintain an internal modification counter (modCount). If the collection's structure changes—such as through an add() or remove() call—without notifying the iterator, the counter becomes out of sync, immediately triggering a ConcurrentModificationException.

1. Use Iterator.remove()

When modifying a collection during iteration within a single thread, do not use the collection's direct remove() method. Instead, use the iterator's own remove() method, which safely updates both the underlying structure and the iterator's internal state.

List<String> items = new ArrayList<>(Arrays.asList("A", "B", "C"));
Iterator<String> iterator = items.iterator();

while (iterator.hasNext()) {
    String item = iterator.next();
    if ("B".equals(item)) {
        iterator.remove(); // Safe and prevents the exception
    }
}

2. Use Collection.removeIf() (Java 8+)

Java 8 introduced the removeIf() method on the Collection interface. It internally handles iteration and safe removal using an iterator or specialized bulk operations, making the code concise and thread-safe for single-threaded usage.

List<String> items = new ArrayList<>(Arrays.asList("A", "B", "C"));
items.removeIf(item -> item.equals("B"));

3. Use Concurrent Collections

For multi-threaded environments where one thread reads while another writes, standard collections wrapped in Collections.synchronizedList() are not enough during iteration. Instead, use classes from the java.util.concurrent package:

  • CopyOnWriteArrayList / CopyOnWriteArraySet: Creates a fresh copy of the underlying array whenever a mutating operation occurs. Iterators traverse a snapshot of the array taken when the iterator was created, meaning modifications will not throw exceptions. This is ideal for read-heavy workloads.
  • ConcurrentHashMap: Uses partitioned segments or CAS (Compare-And-Swap) operations and provides weakly consistent iterators that reflect the state of the collection at or after the iterator was created, without throwing exceptions.

4. Iterate Over a Snapshot or Copy

If using a concurrent collection is not feasible, iterate over a defensive copy of the collection while modifying the original.

List<String> items = new ArrayList<>(Arrays.asList("A", "B", "C"));

for (String item : new ArrayList<>(items)) {
    if ("B".equals(item)) {
        items.remove(item); // Safe because we iterate over the copy
    }
}

5. Collect Modifications for Batch Processing

Instead of altering the collection during the loop, record elements to be added or removed in a temporary collection, then apply the changes afterward.

List<String> items = new ArrayList<>(Arrays.asList("A", "B", "C"));
List<String> toRemove = new ArrayList<>();

for (String item : items) {
    if ("B".equals(item)) {
        toRemove.add(item);
    }
}

items.removeAll(toRemove);

6. Explicit Synchronization

When using synchronized wrappers (such as Collections.synchronizedCollection()), you must manually synchronize on the collection block while iterating to ensure no other thread modifies the structure during traversal:

Collection<String> syncCollection = Collections.synchronizedCollection(new ArrayList<>());

synchronized (syncCollection) {
    for (String item : syncCollection) {
        // Safe from modifications by other threads holding the lock
    }
}

Java Regex Pattern Internal Data Structure

In the Java standard library, the java.util.regex.Pattern class does not compile regular expressions into a traditional deterministic finite automaton (DFA) table, nor does it retain the raw expression string for runtime parsing. Instead, the Java Virtual Machine compiles a regular expression into an in-memory directed graph of specialized Node objects that represent a backtracking Non-Deterministic Finite Automaton (NFA). This article breaks down the internal structural representation of a compiled Pattern, the hierarchy and roles of its underlying nodes, and how the compilation process builds this execution graph.

The Foundation: The Node Graph

At the core of a compiled Pattern is an internal abstract class named Pattern.Node. Every element of a regular expression—such as character literals, wildcards, quantifiers, group delimiters, and anchors—is converted into a concrete subclass of Node.

The compiled pattern maintains a reference to the entry point of this graph via an internal field called root:

transient Node root;

Each Node instance holds a reference to the subsequent node in the execution path via its next field:

Node next = Pattern.accept;

The terminal boundary of a pattern chain is marked by Pattern.accept, a sentinel Node implementation that signifies a successful match when reached by the engine.

Structural Node Specializations

Java does not use a single generic node with an opcode. Instead, it relies on polymorphism and custom node implementations to evaluate specific regex operations. Key subclasses include:

  • Literal Strings (Slice, SliceS, SliceI): Contiguous sequences of literal characters are coalesced into a single slice node rather than a chain of individual character nodes. Slice handles single-byte or standard character sequences, while variants like SliceI implement case-insensitive matching, and SliceU handles Unicode-aware case folding.
  • Character Predicates (CharProperty, BmpCharProperty): Represent individual character tests, character classes (such as [a-z]), and predefined classes (such as \d or \w). These nodes evaluate characters using bitmasks or functional predicates.
  • Alternation (Branch): Implements the pipe operator (|). A Branch node maintains an array of alternative paths (Node[] atoms) and a pointer to the convergence point (Node conn), representing the join point after any of the alternative branches complete.
  • Capturing Groups (GroupHead and GroupTail): Capturing groups are delimited by a pair of cooperating nodes. A GroupHead node stores the group index and saves the current character index; the matching flow then passes to the group's inner nodes. The GroupTail node completes the sequence, updates the group's match boundaries in the Matcher, and continues down next.
  • Quantifiers (Curly, GroupCurly, Loop, Prolog): Quantifiers (*, +, ?, {n,m}) compile into complex loop constructs:
    • Curly: Manages greedy, reluctant, or possessive quantifiers applied to single-character nodes or fixed-length matches.
    • GroupCurly: Handles quantifiers applied to multi-node structures or capturing groups.
    • Prolog and Loop: Used for general greedy loops, separating the initialization of the quantifier from the repeated iteration and condition checking.
  • Anchors (Start, End, Dollar, LastMatch): Zero-width assertions that check boundary conditions without consuming input characters.

Compilation: From Syntax Tree to Linked Nodes

When Pattern.compile(String regex, int flags) is invoked, an internal compiler parses the regex string using recursive descent. Instead of generating an explicit Abstract Syntax Tree (AST) that is evaluated at runtime, the compilation directly constructs the linked Node execution structure:

  1. Tokenization and Parsing: The parser reads the pattern linearly.
  2. Node Creation: Syntactic tokens are instantiated as their respective Node subclasses.
  3. Pointers Assignment: As sub-expressions complete, the compiler links the next field of upstream nodes to downstream targets.
  4. Optimization Passes: During compilation, consecutive character literals are merged into single Slice nodes, redundant loops are reduced, and prefix information (such as initial literal strings or required first characters) is extracted into pattern fields (matchRoot, buffer, or predicate) to enable fast-path checks before the full graph traversal begins.

Runtime Interpretation by the Matcher

The java.util.regex.Matcher acts as the execution engine for the data structure assembled in Pattern. It maintains runtime state, including the input character sequence, group index arrays, and current offsets.

Matching is executed via the match method defined on Pattern.Node:

boolean match(Matcher matcher, int i, CharSequence seq)

During execution:

  • The Matcher passes its state along with the current input index i to the root node.
  • Each node performs its condition test. If successful, it invokes next.match(matcher, newIndex, seq).
  • If a node fails to match, it returns false, causing the JVM call stack to unwind to the previous branch point (backtracking).
  • If execution reaches the terminal accept node, the method returns true, and the engine records the end of the matching sequence.
